# HiAgent 数据建模师 V5

日期：2026-10-14。状态：独立候选版本，待内网测试。V1～V4 保留；不能默认 V5 已部署。

## 本次设计

用户明确的运行方式是：内网没有独立向量数据库，有可用知识库；KB SKILL 先发现相关数据和标识，DB SKILL 再核验存在性、查询精准信息及完整数据。主提示词统一协调工具、确认歧义、展示答案和收敛问题。

V5 据此重写五个运行文件。新对象提供英文标识也先尝试知识库；不沿用旧版“精确名称直接绕过 KB”的入口。已定位及核验的数据复用，不为同一对象或每个成员重复召回。结构 DB 取得的代码名称作为下一阶段字典 KB 的定位输入，字典 DB 再核验和取值。

| 层级 | 职责 | 不应承担的工作 |
| --- | --- | --- |
| KB SKILL | 使用真实知识库定位，提取表、字段、类型和值标识及关系线索 | 最终精准答复、完整列表、证明数据库存在或不存在 |
| DB SKILL | 对定位结果做只读核验，按范围取精准/完整数据 | 语义扩词、发现未知对象、替用户选近似类型或版本 |
| 主提示词 | 识别输出目标，推进依赖、合批、复用、确认或停止，组织层级答复 | 硬编码业务问句、用常识补缺失事实、让 SKILL 相互循环调用 |

主提示词按通用目标输出和依赖组织流程，SKILL 按输入、步骤、输出与结束条件组织。具体表名、字典名、业务问句、版本例子只在本文验收材料中出现；运行文件只含通用规则、真实字段定义和通用 SQL 条件。

## 协调与回答原则

先确定用户所需的最终结果，再按依赖推进。有表字段关系就先确认父对象；独立字典问题不用查表。成员枚举只有取到成员或明确说明未完成原因才算答到目标，不以“定位字典成功”结束。

知识库有标识才进入数据库核验；缺少英文标识但有真实中文名可以核验。没有召回或标识不足时收敛问题，不走数据库兜底。知识库片段数量不代表完整数据，最终全部成员在 DB 的已确认范围内取得。

数据库确认对象存在，不代表语义与用户原词相同。只有唯一精确匹配或用户选择才采用；近似、多类型、版本不明即停在当前层级。其他独立请求继续完成，候选问题编号明确，用户选择后保留原输出目标。

本部署 related 两列仍按已确认含义处理：英文匹配 `code_table_en_name`，中文匹配 `code_table_cn_name`，两者矛盾则报告冲突。不编造独立注释、层级或父级字段，不将业务描述充当表注释。

每回合每类 KB 最多一次，DB 最多八次；每目标每定位阶段最多三次实际执行，包含 KB、DB、计数和纠正。取数分页另受全局预算及每结果集最多五页约束。这些是提示词约束，不是已知的平台硬限制；没有召回时也不需要用满三次。

全量请求不能自行加固定 LIMIT。核对实际 SQL 与总数，必要时一次同条件计数；工具允许修正的截断最多纠正一次，仍受限只能使用真实分页能力或明确报告不完整。提示词不能保证取消工具层限制。

用户答复以简短结论、已完成层级表格和必要的一个选择问题为主。未命中只索取最早缺少的一项信息；工具异常说明原因；越界说明资产问答范围。最终资产事实和展示候选都由 DB 核验，知识库只标定位来源。

## 内网验收：例子只用来测试

以下均为验收输入，不应再复制进运行文件。真实标识由内网数据替换；同一类别至少使用两种不同措辞，检查规则是否泛化，而非只命中固定句子。

| 类别 | 测试输入方向 | 应观察到的行为 |
| --- | --- | --- |
| 完整名称 | 表/字典的英文名、中文全名 | 实际 KB 检索在先，DB 核验在后；没有偷偷走直接 DB 入口 |
| 用途定位 | “存款记录在哪个表中？”与另一业务用途 | 结构 KB 给真实候选，DB 核验；近似对象让用户选 |
| 字段含义 | 已知表中的一列，以及另一列的业务描述 | 结构 KB 定位、结构 DB 给精准字段；保留所属表 |
| 字段字典 | “个人客户存款表科目代码码值字典”及不同表字段 | 表/字段确认后读取 related 名称，字典 KB 定位、字典 DB 核验并列值 |
| 字典身份 | “该字段的字典是哪个？” | 同样核验依赖和映射，但不默认展开全部成员 |
| 字典枚举 | “交易类型有哪些类型？”与另一状态枚举 | 字典 KB→字典 DB；确认类型后继续返回码值及含义，不输出无关字段章节 |
| 指定值/反查 | 已知类型中问一个值、裸值、按描述找值 | KB 提供实际标识和上下文，DB 按原样值与明确范围查询；不数值化、不擅选适用类型 |
| 版本歧义 | “国民经济行业代码”召回多个相似版本 | DB 批量核验候选后请用户选，不默认某版本；选择后继续原目标 |
| 父对象未找到 | 表知识库未召回或候选在 DB 未匹配 | 不查子字段/字典；说明未定位或未核验，索取表标识；不全库兜底 |
| 子字段未定位 | 表已核验但字段无精确/相似项 | 从已确认表取实际字段并列出；不换表，不造字段 |
| 多目标 | 多表多列、多类型多值、共享字典与独立失败项 | 同阶段合批，保留配对；不丢失败项、不重复共享对象、不因一项歧义阻塞全部 |
| 集合请求 | 跨表查列、多个类型出现相同值、目录或共同/差异 | 查询范围与用户原意一致；明确集合不强迫只选一个，不能把 KB 片段范围冒称全库 |
| 完整性 | 300 多码值、实际 SQL 被加 LIMIT、恰好 100 条 | 用执行证据和同条件计数判断；合法分页、不重复第一页、不因数量多再询问是否列全 |
| 证据冲突 | related 名称矛盾、同码不同义、缺失描述或层级 | 保留冲突和缺失，不能推断版本、码长层级或未列值 |
| 续问与停止 | 用户选候选后续问、重复页、权限失败 | 继续原目标并复用真实结果；已结束分支不重启；错误不是不存在 |
| 收敛与越界 | 缺表名、缺类型范围、无关问题及业务实时数据 | 给最早缺口的具体补充方向或候选；说明实际服务范围，不凑查询 |

记录原问题、后续选择、实际 KB/DB 执行轨迹、完整回答、正确结果与耗时。KB 调用顺序和召回标识是本版重点，不能只看最后答案。用户曾反馈的案例用于回归，另加不同业务对象检验通用性。

## 本地检查与限制

```bash
python3 -B check_contracts.py
```

检查四个入口、KB→DB 文档契约、运行文件无具体业务案例，以及六个通用 SQL 模板。用内存 SQLite 验证批量、真实字段映射、配对过滤、前导零、冲突/重复计数和执行层截断的后果。

该检查不执行真实 HiAgent 检索或模型，不能证明实际工具顺序、召回效果、退出或友好响应已经通过；内网需按上表验收。真实方言、分页接口和限制来源仍以用户平台为准。不同版本同时改提示词和 SKILL 后，比较的是整套配置。
