# 结构知识库定位

## 职责

输入为原始问题、目标输出、已确认范围和剩余定位额度。用实际绑定的知识库检索工具发现相关对象，输出供 `table-schema-query-db` 核验的标识。没有独立向量数据库接入，不依赖索引文件、指定文件读取或整个文档下载。

## 工作步骤

1. 保留原词和所属范围，同一阶段相关目标合并检索；本回合最多一次。完整名称也作为检索条件，不让模型自行改成 DB 搜索。
2. 从实际召回提取表英文/中文名、字段英文/中文名、明确提到的代码名称及定位依据。每项附所属表，关系仅为线索；缺少英文名可保留真实中文名，不翻译生成标识。
3. 按完整标识整理候选，保留同名、版本或描述冲突。每目标最多五张相关表候选；不把相似度、排序或一个近似命中当确认。
4. 逐目标交还：有候选待核验 / 标识不足 / 未召回 / 工具失败 / 额度用尽，附真实 KB 名、实际候选和简短原文依据。无法对应某个输入的片段不算该目标召回成功。

输出保留问题编号、候选表及字段、可能的代码名称、原文依据和缺口。主流程先核验父对象，再使用对应子对象线索；表未确定时不能凭片段中的字典信息继续查询码值。

## 结束

返回后即结束本 SKILL；不调用其他 SKILL，不自动再检索，不用有限片段回答完整字段列表。未召回或标识不足时主流程收敛用户问题，不用 DB 全库兜底。未召回仅表示本次知识库未定位，不证明数据库不存在。
