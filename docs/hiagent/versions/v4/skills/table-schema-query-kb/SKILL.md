# 结构知识库定位（V4）

输入是原问题、当前阶段、已确定表范围及剩余定位次数。精确名称优先结构 DB；用途/描述才直接检索。只用实际绑定的知识库，不读索引、不指定文件、不执行 SQL，不调用其他 SKILL。

1. 每回合最多检索 1 次，也占当前目标定位最多 3 次中的 1 次；没有剩余额度就不调用。多个相关目标可一次提交，保留各自原词和编号。
2. 表未确认时只提取表英文名、表中文名、表定位依据。片段中的字段、代码名称、字典代码不得进入下游查询；**只有字典线索而没有表标识，不算表候选**。
3. 候选只来自真实片段，缺少英文名可保留真实中文名供核验；两种名称都没有就算无法定位，不造表名。每目标最多 5 个相关表，不把相似度或 Top1 当确认。
4. 返回每项的状态：有表候选待 DB 核验 / 未召回表候选 / 检索失败 / 定位额度用尽，并附真实 KB 名和简短依据。漏召回与失败都不等于数据库不存在。
5. **未召回表候选立即结束该定位分支**，不建议模糊 SQL、查所有表、再换词或改查字典。即使片段写“科目代码对应 FIN_PROD_CD”，没有已核验表也不能据此继续。

| --- | --- | --- | --- | --- |
| <输入编号> | <原文或未提供> | <原文或未提供> | <实际片段> | <工具返回的 KB 名；缺失写名称未返回> |

这是内部候选。主流程尚有定位额度时批量结构 DB 核验；没有额度则说明表未完成核验，不把 KB 候选展示为 DB 资产。候选不存在于 DB 时，主流程结束；只剩近似候选时由用户选，不自行继续字段查询。

表已确定而问题是字段含义/码值时，主流程直接用结构 DB 读取当前表字段，包括 `related_column_en`、`related_column_cn` 的真实代码名称；不通过本 SKILL 代替字段取证。
