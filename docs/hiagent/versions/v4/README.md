## 定位与取数的边界

“最多 3 次”指一个目标的一层定位，包含该层的 KB、DB、计数和纠错，不是每个 SKILL 各三次，也不是整条“表→字段→字典→码值”只能调用三次。固定路径：

- 有精确名称：DB 一次；零行才 KB 一次；有对象候选才 DB 批量核验一次。KB 未召回立即结束，最多到第三次，不再模糊查询或查所有表。
- 只有描述：KB 一次；未召回立即结束；有候选再 DB 核验。近似候选需要用户选择。
- 候选完整性仍不明且定位额度已耗尽：展示已核验候选供选择，或明确核验未完成；不能为证明唯一再无限计数。
- 一旦结束/待确认，不在同回合重新打开该分支。其他独立问题可继续；同一依赖链不能伪装成独立字典问题绕过阻断。

单次精确查询零行不等于整条定位已结束：还允许固定路径中尚未使用的 KB 步骤。KB 空、候选 DB 核验空或额度用完后才进入不可重开的终止状态，避免过早误报未找到。

全局仍为每回合 DB 最多 8 次、每类 KB 最多 1 次。已确定对象的分页受剩余 DB 次数和每结果集最多 5 页约束。V3 的 3 页上限在每页 100 行时无法容纳 301 行；V4 的页数上限允许四页完成此类查询，但这不代表实际工具已支持分页，也不保证复杂链路总能在本回合取完。

如果模型仍忽略这些停止条件，需要检查 HiAgent 实际绑定/生效正文及调用轨迹；平台若已有可用的工作流条件节点、执行次数限制，可将同样的前置条件放在那里。提示词只是模型行为约束，本次没有创建或配置这些平台能力。

## 代码名称和引用的处理

| 当前字段真实 DB 行 | 处理 |
| --- | --- |
| 英文名称有值，中文缺失 | 按英文代码核验字典；中文展示字典实际返回值，不猜原字段缺失内容 |
| 英文、中文均有值 | 英文优先，中文核对；矛盾则保留证据，报告映射冲突 |
| 只有中文名称 | 批量精确匹配字典中文名，存在同名/版本歧义则请用户选择 |
| 两者均缺失 | 再看当前字段业务描述中的明确引用；仍无依据则说明缺口，不从字段名推断 |
| 只有 KB 说字段对应某类型 | 不能作为 DB 映射结论；尤其不能跳过表/字段确认 |
| 用户选某类型帮助解释值 | 可继续查值，标注“用户选定用于查询，引用未核实” |

英文映射已核验、字典中文名缺失时，说明中文名称未核对即可，不把缺失等同冲突。码值按字符串保留；独立表/字段/字典注释仍没有已提供的数据库列，显示“未提供”。

行业版本确认后也不能臆造层级：当前四个字典字段没有专门的级别、父级代码。DB 描述明确给出时可引用；否则展示真实码值、标明层级信息缺失，并请用户补该版本层级规则。不能把码长或前缀推断当数据库事实。
