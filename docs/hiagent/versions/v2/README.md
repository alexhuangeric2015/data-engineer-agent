# HiAgent 数据建模师 V2 对比测试包

创建日期：2026-10-12。状态：待用户内网实测，尚无效果结论。

## 版本与唯一改动

| 版本 | 主提示词 | 四个 SKILL | 用途 |
| --- | --- | --- | --- |
| A：现有基线 | `docs/agent-prompt/数据建模师.md` | `docs/skills/*/SKILL.md` | 保持现状，作为对照 |
| B：V2 | 本目录 `agent-prompt/数据建模师.md` | 本目录 `skills/*/SKILL.md`，与 A 逐字一致 | 仅比较主提示词变化 |

V2 将流程集中为“回答许可 → 入口选择 → 阶段决策 → 查询节制 → 展示模板”，减少分散说明，把“SKILL 返回后继续还是停止”放进阶段决策表。数据库核验、候选确认、注释缺失、关联证据、全量与前导零等边界保持一致。

按 Unicode 字符数（含空白）计，主提示词由 5559 字符变为 3933 字符，减少约 29.2%。这只是文本长度变化，不能等同于 token、耗时或准确率提升。

四个 SKILL 的内容和注册名称没有变化。测试时可以继续使用现有绑定，不必替换 SKILL；本目录副本用于冻结版本和携带到内网。若同时调整模型、工具或 SKILL，就不能把差异归因于主提示词。

## 应用方法

1. 在测试智能体中使用基线 A，保留实际主提示词内容及调用记录；四个 SKILL、数据库、知识库和模型配置保持现状。
2. 只将主提示词替换为本目录 `agent-prompt/数据建模师.md`，运行 B；不要把本 README 填入模型提示词，不要让 A、B 两份主提示词同时生效。
3. 如需传输，配套 ZIP 包仅用于搬运五个运行文件和本文；不假定 HiAgent 支持整包直接导入。四个 SKILL 使用现有注册名称，不能同时绑定同名的 A/B 两套入口。
4. 同一问题使用相同业务目标、数据状态与模型参数。单轮问题从新会话开始；多轮确认保留各自上下文，并选择同一个真实表/字段/字典，不能只机械回复相同序号。
5. 每题先各测试一次；结果有差异、耗时波动大或出现偶发绕过 DB 时，再各重复三次，交替测试 A/B。测试完成后可以恢复基线正文。

本轮不修改原主提示词及四个原 SKILL，不新增平台工具、元数据字段或项目运行代码。没有访问内网或修改 HiAgent 实例。

## 建议优先比较的问题

方括号中的标识先替换为内网实际存在且可以核对的对象；A/B 必须使用同一替换值。不存在、截断、冲突等场景只在实际可用时测试，不修改生产元数据制造案例。

| 编号 | 问题或步骤 | 正确行为的观察点 |
| --- | --- | --- |
| Q01 | 身份类型有哪些？ | 有实际字典 DB 查询；若只找到角色类型，先确认，不直接把角色码值当身份类型 |
| Q02 | 交易表中的交易状态有哪些类型/码值？ | 表不确定先核验候选并确认；字段、字典和码值严格按阶段推进 |
| Q03 | Q02 后选择同一真实目标表，再选择目标字段/字典 | 能继续原问题；不要求重述；关联未证明时不宣称已绑定 |
| Q04 | [真实表英文名] 的 [真实字段英文名] 是什么意思？ | 跳过结构 KB；单字段仍有 DB 证据；只展示需要的信息 |
| Q05 | [真实表英文名] 中的 [实际不存在且无相似项的字段描述] 是哪一列？ | 展示已确认表全部已取得字段，不造列、不转查其他表 |
| Q06 | [包含 300 多码值的真实字典代码] 有哪些码值？ | 直接完整输出；核对完整性依据与实际条数；不再询问是否列全 |
| Q07 | [真实字典代码] 下 [带前导零的真实码值] 是什么意思？ | 跳过字典 KB；保留前导零；一个值不默认展示整个字典 |
| Q08 | [实际跨类型出现的码值] 是什么意思？ | 查 DB 候选对照，请确认类型，不只挑一个含义 |
| Q09 | [真实表英文名] 的 [有多个近似列的业务描述] 有哪些码值？ | 给同表字段候选；字段未确认前不查整类码值 |
| Q10 | 查询实际存在的表、字段和字典，观察注释、来源与冲突 | 来源区分数据库表与知识库；缺失注释写未提供；冲突描述不静默合并 |
| Q11 | 实际工具失败或返回截断时的查询（若环境出现） | 保留上游已核验信息；失败不说不存在；局部数据不称全量；有限停止 |
