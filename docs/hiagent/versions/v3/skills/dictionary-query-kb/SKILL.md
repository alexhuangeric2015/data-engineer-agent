# 字典类型候选定位（V3）

输入：带问题编号的原词、业务描述、已确认字段范围和 DB 描述。输出：逐问题的候选类型标识、召回依据及状态。只调用实际绑定的字典知识库，不执行数据库，不调用其他 SKILL，不输出最终码值答案。

1. 精确字典代码/完整中文名优先字典 DB。只有码值或想按码值含义反查也优先 DB，避免向量片段遗漏类型。描述、近似名称或精确未命中才用本 SKILL。
2. 本回合字典 KB 最多 1 次；多个相关目标可合并检索，但保留每项原词、所属表字段与问题编号。不能把“身份类型”自动替换成“角色类型”。
3. 只从实际片段提取 `code_table_en_name`、`code_table_cn_name` 及简短依据。`code_value`、`code_desc` 可以帮助召回类型，但码值描述不是字典独立描述。代码缺失就写“未提供”，不按字段名、后缀或中文生成。
4. 每个待确认目标最多提交 5 个候选类型，按代码去重但保留名称冲突；不靠 Top1 或一个命中确定目标，不编造相关度。
5. 每个输入目标返回候选待核验 / 标识不完整 / 本次未召回 / 检索失败。漏召回与失败都不能说 DB 不存在。不依赖索引、指定知识文件读取、完整文件下载或再试一组同义词。

| 问题编号 | 所属表字段（若有） | 字典代码 | 字典中文名 | 召回依据 | 定位来源 |
| --- | --- | --- | --- | --- | --- |
| <输入编号> | <已确认范围或无> | <片段原文或未提供> | <片段原文或未提供> | <简短片段> | <工具返回的 KB 名，缺失写名称未返回> |

主流程将已知候选代码合并交给 `dictionary-query-db` 核验，代码缺失可按真实中文名核验。DB 证实类型有记录，也不证明它就是用户的意思、与当前字段绑定或码值全集已获取。选择和最终答案由主流程完成。

本 SKILL 不向结构 KB 来回跳转，不输出全部码值，不把同名知识库当成数据库表 `data_asset_code_kb`。返回候选或状态后结束。
