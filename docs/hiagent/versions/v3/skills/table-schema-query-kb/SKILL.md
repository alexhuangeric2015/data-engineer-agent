# 表与字段候选定位（V3）

输入：带问题编号的原始名称/用途/字段描述，以及已确定表范围。输出：逐问题的候选标识、定位依据和召回状态。使用实际绑定的 HiAgent 知识库检索；不执行 DB，不调用其他 SKILL，不替用户选对象。

1. 有精确表/字段标识或完整中文名时，主流程优先结构 DB；只有描述、用途、名称近似或精确未匹配时使用本 SKILL。
2. 保留原词和每个目标的范围。同一业务上下文的多个目标可放入一次检索，明确列出各问题；不要把不同表的同名列合为一个目标。当前回合结构 KB 最多 1 次。
3. 不读取索引、不指定知识文件、不假设能取得整个文档。只提取实际片段包含的表英文名、中文名、字段标识及明确提到的字典候选；不能从缩写或中文翻译造英文标识。
4. 每个待确认目标最多提交 5 张相关表，按明确名称和业务范围优先，保留冲突。只有片段明确说了用途才能记录该线索；字段描述不能自动上升为整表用途。工具没给分数时不编造分数。
5. 每个输入目标都返回一个状态：候选待核验 / 标识不完整 / 本次未召回 / 检索失败。合并检索漏掉某个目标不证明它不存在；不轮换关键词重试。

这些是内部线索。主流程将所有已知表标识合成一次 `table-schema-query-db` 核验；标识不完整时可用真实中文名精确核验。最终中文名、字段和业务描述以 DB 为准；KB 用途或引用线索未经 DB 支持只能用于定位，不能作为确定事实展示。

仅一个近似候选仍需主流程确认；同名字段必须带表。查到、未召回或失败都立即交还主流程，不向字典 KB 转跳、不回调自身、不直接列码值。
