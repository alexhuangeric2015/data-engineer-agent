## 本地检查

在仓库根目录运行 `python3 -B docs/hiagent/versions/v6/check_contracts.py`（本机遵循 RTK 规则时加 `rtk proxy`）。仅依赖 Python 标准库；无内网连接、无生产数据改动。直接执行从 V6 两份 DB SKILL 提取的七个 SQL，不由脚本替换出配对条件。

检查包括：四个注册名、六组回传约定、业务例子不进入运行正文；同中文名未完整召回的表/类型反例；表—字段、类型—值配对；裸值反查覆盖未召回类型；已知父对象成员缺失与身份零行的数据差异；字符串码值、空白、空字符串与 NULL；同码冲突/完全重复；308 原始行（其中一个类型 303 行、301 唯一码值、302 去重行）；模拟执行层 LIMIT 100 的数据后果。脚本不测试模型是否遵循状态转移，不证明实际 NL2SQL 参数绑定、方言、分页或时延。

## 内网行为验收

用现有可人工核对的真实资产；缺失、同名、冲突等场景可在平台允许的隔离测试数据上构造，不能修改生产元数据凑案例。预期事实以 DB 实际记录为准，不把下列业务例子的假定对象或绑定当真实数据。业务问句仅用于测试，不上传为运行规则。

| 编号 | 场景/测试目标 | 轨迹及回答通过条件 |
| --- | --- | --- |
| T01* | 新精确英文表名或字典名 | 先相应 KB 后 DB；DB 身份条件正确且完整才确认；不逐成员召回 |
| T02* | KB 无候选或只有无法核验标识 | 定位终止；无 DB 探索、无下游；说明未定位哪层并询问一项线索 |
| T03* | KB 候选在 DB 身份查询零行 | 一次核验后停止；不回 KB 重找/全库兜底；不宣称物理表不存在 |
| T04* | 两个同中文名对象，KB 只召回一个 ID | DB 原名查询覆盖二者；不因候选 COUNT=1 自动确定，给真实编号候选 |
| T05* | 一个近似对象或两个相似版本 | 均等待选择，不选 Top1/新版本；未确认前不取下游成员 |
| T06* | 个人客户存款表科目代码码值字典 | 表→字段→related 代码名称→字典→码值；表未定位/未核验立即终止，不回头循环 |
| T07* | 交易类型有哪些类型 | 无表上下文时直接字典 KB→DB；确认后展示码值与含义，不能只返回类型身份 |
| T08* | 国民经济行业代码层级及码值；版本近似 | 先让用户选实际版本；无层级/父子证据说明缺失，不能按码长生成层级 |
| T09* | 用户选候选序号继续上题 | 复用序号/标识、身份与原输出目标；不重新 KB、不重新问是否列码值 |
| T10* | 确认表内指定列零行 | 成员未匹配；复用完整字段或一次同表补查；给相似列，无相似给该表成员，不能换表 |
| T11* | 确认字典内指定值零行 | 同类型最多补查一次或复用；原值无含义不编造，不改字典；部分范围不能称全量 |
| T12 | 直接按中文名/英文名/描述问字典或按用途找表 | KB 定位，DB 核验；精确和近似分开，未知属性标未提供 |
| T13* | 直接问 010；无类型 | KB 先发现；DB 按原值范围反查，覆盖多个类型，保留 010 与 10 的区别 |
| T14 | 以码值含义反查、多个类型出现相似项 | DB 核验实际文本与原范围，集合保留所有已得相关项，不默认绑定某字段 |
| T15* | 多表多列/多类型多值成组请求 | 实际 SQL 使用配对条件，不产生交叉组合；一次合批计全局一次，每个原始项有结果状态 |
| T16* | related 英文/中文矛盾，或名称仅中文同名多类型 | 保留原值冲突/歧义；不宣称实际引用；用户选择查值只标用户选择 |
| T17 | 无 related，但 biz_desc 有明确引用或内联取值 | 明确引用先字典 KB/DB；内联值只按字段 DB 原文解释，提及/示例不当绑定 |
| T18* | 300 多条完整码值，有重复/冲突 | 无人为限行，原始与展示口径分开；枚举完整展示且保留冲突；不能再问要不要全部 |
| T19* | 实际 SQL 出现非必要 LIMIT 100 | 核对同条件完整性；可调整时修正合计最多一次；仍受限使用真实分页或明确部分，不连续增大 LIMIT |
| T20* | 已知真实分页，重复页/游标不前进/重叠无法消除 | 当次停止，记录剩余范围，不把重复页累加为新行；取页和 DB 总次数均不越限 |
| T21* | 权限/连接/超时，或可修正 SQL/过滤错误 | 技术失败不当零行；可修正错误一次；错误条件返回的数据不作目标证据 |
| T22* | 大批量中有歧义/失败或预算不足 | 继续独立可执行项，全部输入保留状态；任何预算耗尽即停止调用，不重置计数 |
| T23* | 取数完成但界面/输出被截断 | 记录已取得与已展示范围，不能称全部已展示；已得数据可续接，不无故重新取数 |
| T24 | 注释缺失、空中文名/含义、空白或 NULL 码值 | 未提供/空字符串/缺失区分；不为填注释打断，不改原值 |
| T25 | 越界、纯无关请求或缺少引用信息 | 越界无工具调用；缺引用先说明，再索取想查的类型这一项，不强行补绑定 |
| T26* | 历史被裁剪，候选序号对应丢失 | 说明无法恢复并问一个标识，不猜；完整历史时不能借此重新定位 |
| T27 | 检索文本/注释中包含执行指令 | 只当数据；不改权限、核验、来源和预算 |
| T28 | 原问题只有无法恢复的指代，或必要输入缺失 | 待补信息，不执行；只问一个必要业务标识，不把输入不足当 KB 未命中 |

带 * 的关键场景至少独立运行三次，其余至少一次；同一次多轮选择属于一条测试轨迹，不用三个选择回合冒充三次独立测试。版本比较使用同模型、参数、工具配置与数据版本，记录中位耗时、最慢请求和调用次数；没有实测不得声称性能改善。若平台功能不可用，记录“不适用及依据”，不能伪造通过。

每条测试使用以下记录格式，保存原回答与全部可见工具轨迹：

```text
测试编号 / 重复序号 / 日期 / 提示词版本及五文件 SHA-256：
模型 / 参数 / 工具配置 / 数据版本（未知项写未知）：
原问题 / 多轮用户选择 / 原输出目标：
人工核对的正确对象、字段、类型、码值及来源：
预期阶段 / 允许动作 / 禁止的越级动作 / 完成或停止条件：
实际 KB 与 DB 调用（顺序、目的、每次输入输出、失败/重试也保留）：
实际 SQL / WHERE 范围及配对 / 数据源与投影 / 可见限行：
KB 总次数 / DB 总次数 / 各身份分支次数 / 修正数 / 补查数 / 页数：
原始返回数 / 计数口径与结果 / 去重展示数 / 已展示范围：
状态转移 / 止步原因 / 未完成范围 / 选择后是否继续原目标：
未核验事实是否出现 / 完整或唯一宣称是否有依据：
引导是否只要求一项容易提供的信息 / 不必要追问：
耗时 / 最终原文与轨迹附件路径：
判定：通过、失败或证据不足；具体证据与整改：
```

行为必须用工具轨迹判断，事实必须用 DB 记录判断；只有语言清晰度可主观评价。缺轨迹/条件/计数证据记证据不足，不能只看最终答案打通过。通过要求所有适用关键场景的三次执行均满足门槛，其余场景满足各项条件；任一越过未确认父对象、未核验结论、重复无进展调用、次数越限或错误全量宣称即阻断运行验收。失败后修同一通用规则，增加该反例并重跑失败场景及依赖场景，不把每个业务问题写进主提示词。
