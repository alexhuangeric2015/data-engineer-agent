## 共同业务合同

- 新对象先 KB 发现，相关标识返回后才 DB 精准核验；KB 无标识结束分支。
- 表→字段→字典→码值依赖逐层确认；独立字典及码值反查走直接业务入口，无需先找表。单目标歧义与集合/比较分开。
- 同阶段合批、保留表字段和类型值配对；明确原名称范围与候选范围，不拿候选子集证明唯一或全量。
- 码值逐行原文展示，保留重复与冲突；SQL 统计类型总量及本次匹配量，表格下方展示 N/M/P/R/D，不能将统计去重用于删除明细。
- 保留 V8 的预算、成员补查、一次修正、真实分页、续问与显式刷新语义。最终整理不重新查询；文字预算不是平台硬门禁。
- 来源及注释缺失如实说明，无匹配/歧义/技术失败分别给一个可行下一步；不要求用户重复原问题。

业务例子不写入运行正文。完整的字段契约和九个 SQL 参考仍在对应 V8 SKILL 中，本版未新加元数据列或 SQL 模板。

## 最小内网对照

复用 [V8固定任务](../v8/eval_cases.json) 和实际业务反馈。隔离测试可准备缺失、冲突、截断等条件；不要为测试修改生产元数据。V8 任务仅作既有输入与预期参考，本版没有生成或继承任何模式成绩。

1. 三种模式采用同一批任务、同一组 SKILL/工具与数据、干净的初始会话；各独立运行三次。涉及候选选择的任务按同样方式回复选择。
2. 尽量保持各模式可比的模型、采样、输出容量、历史保留设置，记录所有模型角色。若模式强制不同组件或配置，明确记录，不能将差异全部归因于提示词。
3. 保存主提示词实际版本、模式、问题与续问、真实 KB/DB 输入输出、生成 SQL、终止原因、最后回答及耗时。分开 SKILL 加载次数、外层工具次数、可见 SQL 次数和模型调用次数；不可见项写未知，不能互相换算。
4. 核对 KB→DB 顺序、上游确认、批量条件及原范围、是否重复调用、是否正确停止、码值原文/行数/统计及来源。分别判断业务完成与规则遵循；正确停止的无结果任务不伪装成成功查到数据。
5. 在满足准确性和完整性后比较耗时和调用数。统计成功任务耗时与失败/部分比例，避免靠提前终止获得表面提速。

截图中的迭代30与输出4096仅为一次配置证据，不是本版推荐固定值。先测实际合法最短路径及平台迭代计数含义，再设置有余量的硬上限；不能随意调低导致字段链路中断，也不靠增加迭代补偿输出截断。若输出容量确实不足，保留数量及未展示范围，不假装已完整展示。
