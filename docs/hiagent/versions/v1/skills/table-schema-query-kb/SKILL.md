# 表与字段候选定位

## 职责与边界

使用实际绑定的 HiAgent 知识库检索工具，将自然语言问题定位为表/字段候选。输入是用户原始业务名称及已确认的表/字段范围，输出是候选标识与召回依据。不执行数据库查询，不返回已确认的字段含义、整表结构或码值；最终展示和追问由主提示词统一完成。

用户已给精确表英文名，或当前问题已有 DB 核验的目标表时，直接交给 `table-schema-query-db`，无需本 SKILL。知识库检索结果不是数据库证据。

## 执行步骤

1. 从原问题提取表名、字段名及业务范围，保留用户原词；已有明确表时只在该表语境内定位，不将“身份类型”自动改写成“角色类型”。
2. 对实际绑定的数据库结构知识库检索一次，可将表名、字段名与范围放入同一查询。不要先查索引文件，不要求工具按指定文件名读取，也不假设能拿到整个 CSV。
3. 只从实际召回片段提取表英文名、表中文名、字段英文名，以及文档明确提出的字典关联候选。没有表英文名的片段标注“标识不完整”，不能造表名。
4. 同表候选去重，优先保留与原词精确对应、范围一致的项，最多 5 张候选表；不同表不能只因字段名相同合并。不要编造分数或把工具的召回排序当成业务确认。
5. 将候选交给 `table-schema-query-db` 批量核验。仅有一个近似候选也不自行选定；DB 核验后仍不确定时，由主流程展示候选让用户确认。
6. 未召回时返回“未召回”，不是“数据库中不存在”；主流程可对用户明确提供的名称做一次 DB 精确核验。检索工具失败时返回失败，不伪造候选、不换词反复检索。

## 提交给主流程的结果

| 项目 | 内容 |
| --- | --- |
| 状态 | 候选待核验 / 标识不完整 / 未召回 / 检索失败 |
| 原始查询 | 用户原词与本次检索范围 |
| 定位来源 | 工具实际返回的知识库名称；未返回则写“名称未返回” |
| 候选 | 下表中的实际召回标识，全部标记为待 DB 核验 |

| 候选表英文名 | 候选表中文名 | 候选字段英文名 | 关联字典候选 | 召回依据 |
| --- | --- | --- | --- | --- |
| <片段明确返回的表名> | <片段中的名称> | <片段明确返回的字段名> | <片段明确提出的代码；缺失则未提供> | <原文中与用户问题相关的简短依据> |

上述表格是内部候选，不直接作为用户答案。表中文名、注释、字段和关联信息都要以后续 DB 结果为准；知识库提出的关联在 DB 无明确映射时，需要用户确认。

## 停止条件

本回合最多一次结构 KB 检索；发现候选、未召回或失败后立即交还主流程。不调用其他 SKILL 来循环定位，不输出“再查一次”，不因为向量切片不足就自行补齐字段。
