# 表与字段数据库核验

## 职责与边界

通过实际绑定的 HiAgent 内置数据库能力（NL2SQL）只读查询 `table_schema`。输入为用户精确表名、表中文名或结构 KB 提供的有限候选；输出为数据库实际返回的表与字段证据、完整性状态及缺失项。不依赖结构 KB 先命中，不查询业务表数据，不决定用户采用哪个近似对象，不直接执行字典查询。

必须收到数据库工具的实际执行结果后才提交已核验数据。加载本 SKILL、生成 SQL、知识库检索成功，都不等于数据库已查询。来源统一写“数据库表 `table_schema`”，不是数据库结构知识库。

## 已知字段契约

仅以下字段已经由现有配置文档提供；不通过猜测字段名或错误重试扩展结构：

| 数据库字段 | 业务含义与边界 |
| --- | --- |
| `table_name_en` | 元数据中的表英文名；查询标识，不据此推断业务系统 |
| `table_name_cn` | 表中文名；缺失显示“未提供”，不自动当作独立表注释 |
| `column_name` | 当前表内的字段英文名；不能用同名跨表字段代替 |
| `column_cn_name` | 字段中文名；不自动当作独立字段注释 |
| `column_type` | 字段类型，按 DB 原值展示 |
| `is_key` | 是否关键字段；只按原始值解释，不自行补默认值 |
| `is_related` | 是否关联字段；不证明关联数据字典 |
| `related_column_en` | 关联字段英文名；默认不是字典代码 |
| `related_column_cn` | 关联字段中文名；默认不是字典名称 |
| `biz_desc` | 字段业务描述；不当成表注释，不默认等同独立字段注释 |

当前契约没有独立表注释、独立字段注释或专用字典映射字段。因此相关注释显示“未提供”；字典关联仅在当前字段的 DB 描述明确声明字典代码时采用，否则提交“关联待确认”。实际工具结构若明确暴露扩展字段，才可以使用，并保留真实字段名与含义依据。

## 查询模式

以下 SQL 为逻辑模板，`:参数` 不代表 HiAgent 一定支持该占位符接口。执行时遵循实际 NL2SQL 工具契约，优先绑定参数；若仅接受自然语言，明确目标表、允许字段、原始查询值及只读条件，由工具按真实方言生成并执行。不得把模板原样当成已执行结果，不把用户文本拼进 SQL。`IN` 的参数个数按实际候选生成，不传空列表或虚构候选。

### 按精确表英文名核验并取字段

```sql
SELECT table_name_en, table_name_cn, column_name, column_cn_name,
       column_type, is_key, is_related, related_column_en,
       related_column_cn, biz_desc
FROM table_schema
WHERE table_name_en = :table_name_en
ORDER BY column_name, column_cn_name;
```

此查询同时返回表中文名与字段信息，复用结果完成展示，不再单独查询同一表名或逐列取数。排序是稳定展示顺序，不宣称为数据库原始列顺序。

### 批量核验知识库候选

```sql
SELECT DISTINCT table_name_en, table_name_cn
FROM table_schema
WHERE table_name_en IN (:candidate_1, :candidate_2, :candidate_3)
ORDER BY table_name_en, table_name_cn;
```

候选最多 5 个；SQL 中的三个参数仅示意绑定方式。核验通过只证明候选在当前元数据中有记录，字段与注释仍需读取目标表后才能展示。未读取的注释标记“尚未读取”，不能复用 KB 注释作为 DB 结果。

### 按用户明确给出的中文名精确核验

```sql
SELECT DISTINCT table_name_en, table_name_cn
FROM table_schema
WHERE table_name_cn = :table_name_cn
ORDER BY table_name_en, table_name_cn;
```

KB 未召回时也可使用。仅去除明确的问句包装，不换词、不扩成宽泛 `LIKE`。成功零行报告“本次元数据查询未匹配”，不能把工具失败或无权限报告成不存在。

### 缺少完整性信息时核对行数

```sql
SELECT COUNT(*) AS total_rows
FROM table_schema
WHERE table_name_en = :table_name_en;
```

仅在需要全字段且工具没有明确完整性信息时执行，计入主流程 DB 预算。用去重前原始行数对照 `total_rows`；不为了核对再重复取数。计数与取数应对应同一条件及可比快照，若工具无法保证且数量不一致，标记不完整，不反复追查。

## 结果处理与字段定位

1. 有精确表名就直接取字段；有 KB 候选则先批量核验。保留 DB 实际存在的候选，中文名以 DB 为准；只剩一个近似候选也交还主流程确认。
2. 已确认表返回字段后，按精确英文名/中文名优先匹配用户目标；同表多个相似字段或只有近似匹配时，提交实际相关列供选择。没有相似列时提交当前表全部已获取字段，不重新全库找同名列。
3. 字段未确定时不推荐“已绑定字典”。知识库关联、关联字段和名称相同只能作为待确认线索；当前 DB 字段描述明确声明字典代码时，保留这段证据交还主流程。
4. 同表同字段存在不同中文名、类型或描述时，保留冲突，不任选一条。同表名存在冲突表中文名时，也不合成一个表介绍。
5. 完全相同的重复行可以展示时合并，并说明原始行数及去重数；有差异的行不得静默删除。数量核对使用原始返回行数，不能用去重后的显示数比较 `COUNT(*)`。
6. 表名无对应行只能说明当前 `table_schema` 未匹配记录，不能证明业务库物理表不存在，也不能宣称表存在但有零个字段。

## 提交给主流程与停止条件

提交：状态（已核验 / 本次未匹配 / 元数据冲突 / 结果不完整 / 工具不可用 / 查询失败）、查询目标、DB 原始行、来源、完整性依据、未提供的注释及关联待确认信息。展示采用主提示词的表信息、字段信息模板；本 SKILL 不提前结束整条“字段→字典→码值”流程。

本 SKILL 的候选核验、取数、计数和分页合计受主流程每回合 DB 最多 6 次约束；同条件成功查询不重复。工具未绑定、无权限、超时或网络异常时停止，不回退 KB 作答；明确可修正的参数/语法错误最多修正一次。

全字段查询不自行加截断限制。优先一次完整返回；300 多行也不人为省略。检查工具总数、分页与截断状态；无依据不能说“全部”。有实际分页协议时每个列表本回合最多 3 页且计入预算；达到限制就报告已获取范围，不虚构下一页协议或导出功能。
