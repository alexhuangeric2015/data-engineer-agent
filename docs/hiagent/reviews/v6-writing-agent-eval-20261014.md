## 按优先级列出的发现

### R1｜P2：自动确认没有明确覆盖 DB 字段映射产生的英文标识

证据：[主提示词确定对象](/Users/alexhuang/workspaces/github/data-engineer-agent/docs/hiagent/versions/v6/agent-prompt/数据建模师.md:37) 的英文分支限定为“用户给出的完整英文标识”；[代码名称解释](/Users/alexhuang/workspaces/github/data-engineer-agent/docs/hiagent/versions/v6/agent-prompt/数据建模师.md:61) 又要求按字段 related 英文代码优先定位。用户只问字段码值时，字典英文代码通常来自结构 DB，用户没有提供该英文代码；related 中文名也可能为空。

本次隔离 SQLite 验证：现有样本 T_A.STATUS 的 related_column_en 为 CODE_A，将 related_column_cn 设为 NULL；用文档 D_ID 模板按 CODE_A 查询，返回一个真实类型 CODE_A/测试字典甲。用户未提供字典名称。这证明查询能够取得精确映射证据，而主控自动确认条件没有明确容纳这个证据来源；不证明 HiAgent 已实际卡在此处。

影响：模型可能额外让用户确认已被精确核验的代码，或者自行把 DB 代码冒充用户输入，执行路径存在解释差异。

建议：明确三种确认依据：用户明确标识、当前字段经 DB 核验的代码名称映射、用户选择已核验候选。DB 映射路径仍需字典 KB 在先、英文逐字匹配、实际查询完整及中文无冲突；KB 自行推断出的英文名不因此获得自动确认资格。

验收：字段只提供英文代码名称、中文为空，用户未给字典名称；实际映射精确且无冲突时继续原码值目标。映射中文冲突或 KB 近似推断时仍停下，不能扩大自动确认。

### R2｜P2：结果集的定义与计数额度粒度不够一致

证据：[结果集定义](/Users/alexhuang/workspaces/github/data-engineer-agent/docs/hiagent/versions/v6/agent-prompt/数据建模师.md:67) 按“同一原目标的获取流程”归为一个结果集，并规定修正不重获计数额度；[完整性规则](/Users/alexhuang/workspaces/github/data-engineer-agent/docs/hiagent/versions/v6/agent-prompt/数据建模师.md:73) 每结果集至多一次同投影/过滤计数。一个原目标可以有身份 DISTINCT 查询、指定成员查询、完整成员补查等不同范围与投影。

规则反例：用户要求一个字典的全部码值；先核验类型并对 DISTINCT 类型查询计数，再取码值。若按原目标把两次查询视为同一结果集，码值查询无法再获得同口径计数，即使回合 DB 预算仍充足；若按实际投影分成两个结果集，又缺少明确定义。成员补查改变范围也有同样歧义。这是文本推演，非真实执行故障。

建议：结果集按任务项、确认对象、阶段、预期投影及业务过滤范围标识。分页和修正沿用原标识；真正改变取数范围的补查使用其自己的完整性口径，仍受一次补查、定位三次和全局八次约束。定义放在预算段一处，不增加新的外部状态 API。

验收：身份计数不能代替成员计数；补查计数须匹配补查范围。修正/分页不能借换结果集重置次数，全局计数不变。

### R3｜P2：跨回合证据复用缺少显式重新核验的失效规则

证据：[续问复用](/Users/alexhuang/workspaces/github/data-engineer-agent/docs/hiagent/versions/v6/agent-prompt/数据建模师.md:31) 保留已取证范围；[成功签名复用](/Users/alexhuang/workspaces/github/data-engineer-agent/docs/hiagent/versions/v6/agent-prompt/数据建模师.md:71) 规定满足覆盖条件就复用，但没有说明用户要求刷新、重新核验或元数据发生变更时如何处理旧证据。

影响：若用户明确要求重新查询同一对象，旧范围和成功签名仍匹配，规则可能继续复用旧值。这不表示用户库已发生变更，也不是要求每个续问都查新数据。

建议：正常候选选择和成员续问继续复用；显式重新核验、已知数据变更或实际上下文限定改变时，使受影响的 DB 事实证据失效，再按当前预算核验。保留身份定位线索，区分“来源已定位”与“事实仍有效”；原候选依赖已变更证据时同步撤销确认。记录取得时点/数据版本，未知写未知，不虚构 TTL。

验收：选择序号不重复查询；明确刷新同对象时有新的 DB 执行证据；已知失效证据不能支持当前完整性或绑定结论。

### R4｜P2：评测场景已齐全，但尚缺固定任务与结果汇总

证据：[28 项场景](/Users/alexhuang/workspaces/github/data-engineer-agent/docs/hiagent/versions/v6/README.md:43) 定义了目标与行为，[记录格式](/Users/alexhuang/workspaces/github/data-engineer-agent/docs/hiagent/versions/v6/README.md:78) 留有人工正确对象栏及版本信息；尚未填入具体测试输入、固定 KB 召回、已知 DB 数据与预期实体/值集合。它目前是验收计划，不是已执行的可重复基准。

[本地脚本](/Users/alexhuang/workspaces/github/data-engineer-agent/docs/hiagent/versions/v6/check_contracts.py:77) 验证文档 SQL 的数据结果，不验证智能体路由/状态。README 已如实说明这个边界；本次不把它当隐藏缺陷。缺少的是模型执行的独立判据与结果汇总，而非更多 SQL 断言。

建议：先固定下文五个核心任务，逐任务保存已知数据、精确问句、多轮输入与正确答案。实际平台原始轨迹保留，必要时人工标注工具类别；测试记录格式不是 HiAgent API。对事实集合、父对象门槛、实际次数、重复页和完成声明采用确定性比对，语言清晰度才使用人工或模型判断。任务与判据和版本一起保存，不能见到答案后改预期。

指标补充：各题通过次数/三次、总体通过率、关键约束违规次数、端到端耗时、KB/DB 次数、非必要澄清次数、成本或实际 token（平台能提供时）。现有记录只有耗时和调用次数，没有成本字段与汇总口径。成本不可得记未知，不能按字符数猜费用。证据不足单列；总体已证实通过比例的分母包含所有适用计划执行，避免排除无轨迹执行抬高通过率；有依据的不适用项单列。

### R5｜P3：主提示词负载增加，领域规则仍可就近收拢

实测文件字符数（含空白，不是 token）：V5 主提示词 3629，V6 为 5489，增加约 51.3%；五份运行文件合计 10076→13716，增加约 36.1%。增加部分来自必要的交接和退出规则，不能据此认定模型性能下降。

[主提示词事实/引用段](/Users/alexhuang/workspaces/github/data-engineer-agent/docs/hiagent/versions/v6/agent-prompt/数据建模师.md:57)、[字典 DB 字段参考](/Users/alexhuang/workspaces/github/data-engineer-agent/docs/hiagent/versions/v6/skills/dictionary-query-db/SKILL.md:27) 和结构 DB 同时承载部分领域解释；引用缺口的响应规则又在主提示词后部出现。依据 Writing for Agents，可把跨阶段协调与领域解释的权威分工再收紧。

建议：主提示词保留目标、依赖、状态、预算、完成条件与回复合同；字段语义及领域核对细则就近保留在负责的 DB SKILL，主控只留必要协调摘要。合并重复否定句为明确目标动作，保留实际 DB 证据、上游门槛、只读与有限退出等硬护栏。四个技能 description 以“结构定位/结构核验/字典定位/字典核验”前置职责，说明不同入口，压缩工具包装解释。由于 HiAgent 指定文件读取未知，不把必需规则藏到新的共享文件。

这是精简候选，不是要求任意缩短：先做有规则覆盖核对的候选版，再用固定任务 A/B 测量。仅凭篇幅不给准确率或耗时结论。

## 推荐的五个固定核心任务

下表是评测设计，尚未执行模型。每任务应在允许的隔离数据中固定问句、记录、召回与预期；具体业务内容只进测试材料。

| 任务 | 固定条件 | 确定性判据 |
| --- | --- | --- |
| E1 关联枚举成功 | 一个表/字段；仅 related 英文名有值；精确字典与已知完整码值集合 | KB→DB 路径有证据；映射类型一致；原值/含义集合正确；不因缺中文映射重复确认 |
| E2 上游未定位 | KB 无相关可用标识 | 无 DB 探索和下游；只要求一项定位线索；不宣称 DB 不存在 |
| E3 歧义与续问 | 两个近似或同名对象；第一轮未选择、第二轮固定选序号 | 首轮只显示 DB 核验候选；选择前不取下游；第二轮继续原枚举，不重查成功身份 |
| E4 完整性及无进展 | 一个已确认类型、301 个已知值；固定截断与重复分页轨迹 | 原始/展示口径明确；计数范围正确；修正不重置额度；无进展停止，部分不宣称全部 |
| E5 批量与刷新 | 两组成对输入，分别有已知码值；续问明确刷新，隔离元数据已知更新 | 无交叉组合；每输入有状态；刷新执行新 DB 查询，旧证据不当新事实 |

上述召回条件是测试前置要求，不代表 HiAgent 已支持注入模拟工具结果。若实际平台无法固定召回，应固定知识库内容/检索配置、保留各次真实召回差异，并据实际轨迹归因；不能据此虚构 mock 接口。刷新中发现新标识时，仍按新对象 KB→DB 路径推进。

每版本每任务至少三次独立运行，V5/V6 共 30 条轨迹；多轮选择包含在各条轨迹内。控制模型、参数、工具配置、数据与会话初始状态一致，尽量交替运行版本减少时间变化干扰。先核对部署内容 SHA-256，之后再比较成绩。三次只能观察初步一致性，不能证明绝不循环或统计显著优越。

| 汇总指标 | 记录口径 |
| --- | --- |
| 通过率 | 满足该任务所有门槛的执行数 / 适用计划执行数；失败与证据不足分别列数 |
| 一致性 | 每任务 0/3、1/3、2/3 或 3/3；不能用总体平均掩盖关键任务不稳定 |
| 耗时 | 每条执行从输入到回答；多轮任务另记录各 Agent 回合耗时并剔除用户等待，保存原始值与中位数/最慢值 |
| 成本 | 平台实际费用/token；不可得写未知，同时报实际工具调用数，不假称调用数等于费用 |
| 澄清 | 必要与非必要分开，用户需回复次数可核对，不要求完全消除有效歧义确认 |

## 已做检查及当前判断

V6 原有本地文档/七个 SQL 检查本次重跑通过；增加的英文-only 映射隔离样例返回一个精确字典身份。它们不测试真实模型执行。当前通过率、运行一致性、成本和端到端耗时均未知，不能给真实 Agent Eval 成绩或最佳版本排名。

可以保留的设计：KB 发现、DB 精准核验、主控协调；失败/未匹配/部分分别处理；只展示 DB 候选；用户选择查值不变成实际引用；没有字典层级证据就不推断；具体业务案例留在测试材料。这些不应为了压缩正文而删除。

建议整改顺序：先 R1 确认依据，再 R2 结果集/次数口径，再 R3 证据失效；随后冻结 R4 核心基准并开展内网重复测量，最后根据测量决定 R5 精简是否值得保留。本次不改 V6 或此前报告，下一版应保留 V6 对照。
