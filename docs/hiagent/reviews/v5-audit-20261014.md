# HiAgent V5 主提示词与 SKILL 联合评审

评审日期：2026-10-14。对象：V5 主提示词与四个 SKILL；辅助读取运行说明、V5 README 与检查脚本。以下严重度按潜在后果排序，属于文档发现和设计风险，不表示已测得 V5 故障频率。V5 的 HiAgent 真实执行未被本次访问。

## 按严重度排序的发现

### H01｜高：未命中的终止条件与同范围补查条件没有区分

证据：[主提示词的停止条件](/Users/alexhuang/workspaces/github/data-engineer-agent/docs/hiagent/versions/v5/agent-prompt/数据建模师.md:28) 将“未命中”列为结束当前分支的条件，而[字段及码值候选处理](/Users/alexhuang/workspaces/github/data-engineer-agent/docs/hiagent/versions/v5/agent-prompt/数据建模师.md:32) 要求精确未匹配时在已确认父对象内提供相似项或完整列表。[结构 DB](/Users/alexhuang/workspaces/github/data-engineer-agent/docs/hiagent/versions/v5/skills/table-schema-query-db/SKILL.md:29) 允许补查完整字段，末尾又强调候选核验零行即结束；“候选核验”和“成员过滤”缺少统一阶段定义。

机制：同样的零行结果，可能被模型解读成终止，也可能被解读成需要补查。它会造成过早回答，或者在“结束”和“继续”之间反复选择。当前证据证明规则边界模糊，不能证明 V5 已实际出现循环。

完善规则：按查询目的区分三种结果，不按某个业务问句区分：

| 结果类型 | 允许动作 | 结束条件 |
| --- | --- | --- |
| 知识库未定位到对象，或定位候选未被 DB 核验 | 返回具体缺口，收敛用户问题 | 本分支立即停止，不查询下游 |
| 已确认父对象内，指定字段/码值未精确匹配 | 若尚无该范围完整结果，至多补取一次该范围成员；否则复用 | 给实际候选并等待选择；仍无可用数据则说明缺口 |
| 全量结果受限或完整性未知 | 一次同条件核对；仅使用支持且前进的分页 | 无进展、无能力、错误或预算不足即报告部分结果 |

规则应写成“状态允许什么下一步”，不能让所有零行都共享一个“未命中就停止”的总句。

### H02｜高：主提示词与 SKILL 没有统一的回传和阶段状态约定

证据：主提示词规定[多目标与续问](/Users/alexhuang/workspaces/github/data-engineer-agent/docs/hiagent/versions/v5/agent-prompt/数据建模师.md:20)、[多个调用上限](/Users/alexhuang/workspaces/github/data-engineer-agent/docs/hiagent/versions/v5/agent-prompt/数据建模师.md:49)、[结束分支不可重开](/Users/alexhuang/workspaces/github/data-engineer-agent/docs/hiagent/versions/v5/agent-prompt/数据建模师.md:50)。但[结构 KB 回传](/Users/alexhuang/workspaces/github/data-engineer-agent/docs/hiagent/versions/v5/skills/table-schema-query-kb/SKILL.md:17) 与[结构 DB 回传](/Users/alexhuang/workspaces/github/data-engineer-agent/docs/hiagent/versions/v5/skills/table-schema-query-db/SKILL.md:70) 使用不同状态集合，没有共同记录当前阶段、允许下一步和已完成目标的最小格式。

机制：同一对象可能被当成新目标重置计数；成员已取到却仍继续定位；用户选择后丢失原来要枚举的目标；预算耗尽后续问又从 KB 重启。三个定位调用、八个 DB 调用和五页上限也没有集中计数记录，存在误计和过早耗尽风险。

完善规则：由主提示词持有一份轻量的内部任务记录，SKILL 回传使用相同字段：

| 必要记录 | 作用 |
| --- | --- |
| 请求编号、原始目标输出 | 防止丢掉批量项和“用户原来要什么” |
| 当前阶段、对象完整标识、已确认父对象 | 防止跨表串列、换类型、越过依赖 |
| 结果状态、阻断原因、允许的下一步 | 区分继续、用户选择、部分结果、终止和完成 |
| 定位来源与 DB 执行证据、实际过滤范围 | 区分召回线索、已核验身份与成员数据 |
| 完整性状态及所覆盖范围 | 防止把局部结果说成全量 |
| 已用次数、最后查询范围/参数/页码、剩余额度 | 防重复和计数重置 |
| 未完成项、唯一待确认问题 | 支持友好收敛和选择后的继续 |

这是主提示词与 SKILL 的回传约定，不是新增 HiAgent 工具参数或已存在的状态 API。平台若支持结构化结果，可按其真实接口落地；否则用固定字段的简短表格或自然语言记录。不得承诺仅靠这份记录就获得程序级硬限制。

完成标准也需要明确：取得对象身份只完成定位；枚举要求所需成员已取得并展示，或明确声明当前是部分结果；实际引用要求结构映射与字典核验一致。用户选定用于查询不升级成数据库引用证据。

### H03｜高：候选范围的完整性不足以证明名称唯一或全范围结果完整

证据：[自动采用条件](/Users/alexhuang/workspaces/github/data-engineer-agent/docs/hiagent/versions/v5/agent-prompt/数据建模师.md:26) 使用“完整名称及限定条件唯一精确匹配”；[集合规则](/Users/alexhuang/workspaces/github/data-engineer-agent/docs/hiagent/versions/v5/agent-prompt/数据建模师.md:34) 要求用户范围内的完整集合。KB [候选数量限制](/Users/alexhuang/workspaces/github/data-engineer-agent/docs/hiagent/versions/v5/skills/table-schema-query-kb/SKILL.md:16) 和 [T1 候选核验 SQL](/Users/alexhuang/workspaces/github/data-engineer-agent/docs/hiagent/versions/v5/skills/table-schema-query-db/SKILL.md:37) 可以只覆盖召回的英文标识子集。字典 D1 有同样的范围问题。

本次隔离验证：增加两个不同英文表名、相同中文表名的元数据对象；模拟 KB 仅提供一个英文候选。候选查询返回 1 个、同条件计数也是 1，但完整中文名在数据库实际匹配 2 个。这个反例使用内存 SQLite，不代表用户库中实际有该数据。

机制：实际取数完整、候选列表完整、用户请求范围完整，是不同命题。COUNT 只能核对被执行的查询范围，不能补救 WHERE 自身范围过窄。在只按 KB 英文候选查询的路径中，模型可能将“候选中只剩一个”误认成“原名称唯一”。

完善规则：

- 内部同时记录用户请求范围、KB 候选范围、实际 DB 查询范围。
- 自动按中文名采用时，DB 必须覆盖该原始精确名称及用户明确限定的范围；不能只核验召回 ID 后断言全局唯一。
- 只得到候选子集时，可展示已核验候选，但不宣称唯一；语义近似仍需用户确认。
- 集合/目录/反查只能在实际覆盖用户范围、且完整性核对成立后说全部。字段集合里“任一”和“同时”必须保持用户原意。
- 保持 KB 在先；DB 的范围核对属于精准核验，不是取消知识库定位或转为语义扩词兜底。

### M01｜中：精准单项查询依赖模型改写全量模板，缺少执行谓词核对

证据：[结构 T2](/Users/alexhuang/workspaces/github/data-engineer-agent/docs/hiagent/versions/v5/skills/table-schema-query-db/SKILL.md:46) 默认按表读取全部字段；[字典 D2](/Users/alexhuang/workspaces/github/data-engineer-agent/docs/hiagent/versions/v5/skills/dictionary-query-db/SKILL.md:46) 默认按类型读取全部码值。正文允许调整条件，但没有规定工具请求应携带的最小信息；主提示词对执行 SQL 的检查主要集中于行数限制。

机制：如果 NL2SQL 照模板取全量，单项查询会额外取数、占预算；执行层再限行时，目标可能恰好不在返回范围内。当前没有内网 SQL 轨迹证明 V5 会这样执行，属于条件性风险。

完善规则：工具请求明确列出查询目的、目标标识、父对象、过滤条件及配对、返回字段、指定项或全量。可见实际 SQL 时核对谓词与原目标是否相符，再核对 LIMIT 与完整性。精准请求优先在 DB 过滤，完整范围补查只在需要候选或用户要求枚举时进行。保留少量通用查询形状，不恢复逐业务问句模板。

### M02｜中：友好性有原则，但没有把不同缺口对应到不同澄清动作

证据：[友好响应规则](/Users/alexhuang/workspaces/github/data-engineer-agent/docs/hiagent/versions/v5/agent-prompt/数据建模师.md:57) 和 [收敛规则](/Users/alexhuang/workspaces/github/data-engineer-agent/docs/hiagent/versions/v5/agent-prompt/数据建模师.md:68) 要求一句结论、表格、最早缺少的一项信息，没有明确如何选择最容易由用户补充的信息、如何解释剩余目标及何时无需追问。

机制：模型仍可能只问“请提供英文名/更多信息”，用户不知道标识时难以继续；元数据缺注释可能被当成用户需补信息；选择后又询问是否列码值；内部的 KB/DB 状态可能变成难读的过程解释。

完善规则：按信息缺口类型生成澄清，不按业务问题硬编码：

| 缺口 | 用户动作与答复要求 |
| --- | --- |
| 多个已核验候选 | 给稳定编号、名称及可核实区别；优先让用户选，不强迫重写英文标识 |
| 没有候选 | 请求用户容易知道的标准名称、别名或用途/范围中的一项；说明这项信息将帮助定位什么 |
| 名称/映射/版本证据冲突 | 展示相关原值，明确待确认的是哪个差异；选择用于查询与确认真实引用分开 |
| 元数据未提供非必要属性 | 标未提供，回答其余已核验信息；不为填满表格打断用户 |
| 全量受限或还有未完成项 | 保留已取得结果，说明剩余范围；不重新问用户是否需要原本已要求的全部 |
| 权限、连接或平台能力缺失 | 说明本次不能核验的原因；业务名称补充不能解决技术错误 |

每次追问只要求一个有助于前进的决定；答复顺序为已确认内容、阻断点、候选/缺口、用户下一步。用户选择后继续原目标。外部答复不暴露内部计数记录，来源和缺失依据仍按用户要求展示。

### M03｜中：行为验收尚未形成可判定、可重复的执行记录

证据：[检查脚本](/Users/alexhuang/workspaces/github/data-engineer-agent/docs/hiagent/versions/v5/check_contracts.py:18) 主要核对文本和 SQL，[配对条件](/Users/alexhuang/workspaces/github/data-engineer-agent/docs/hiagent/versions/v5/check_contracts.py:85) 由检查脚本自行替换；它不验证 NL2SQL 是否实际生成相同条件。[README](/Users/alexhuang/workspaces/github/data-engineer-agent/docs/hiagent/versions/v5/README.md:72) 要求保留轨迹，但没有每题的具体判定字段和重复运行口径。

本次重新运行原检查通过；不能将此结果解释为通过实际路由、循环退出或用户体验验收。README 已如实写了这个限制，问题是验收闭环仍未完成。

完善规则：每个回归任务记录请求与预期输出、预期阶段、允许动作、实际 KB/DB 次数、执行条件、停止原因、是否有未核验结论、用户选择后的结果及耗时。关键路径至少重复三次；版本比较保持模型、配置和数据状态一致。阶段行为用工具轨迹判定，事实用人工可核对数据判定；只有文案表现才适合主观评价。

应覆盖：KB 无召回、候选 DB 零行、已确认父对象内成员零行、同名对象不全召回、版本歧义、错误重试、分页不前进、批量部分失败、续问恢复及输出截断。具体业务例子仍只放测试材料。

### L01｜低：预算和退出规则重复分布，步骤与参考规则仍可收拢

证据：主提示词[预算及退出段](/Users/alexhuang/workspaces/github/data-engineer-agent/docs/hiagent/versions/v5/agent-prompt/数据建模师.md:49)、结构 KB [步骤和结束](/Users/alexhuang/workspaces/github/data-engineer-agent/docs/hiagent/versions/v5/skills/table-schema-query-kb/SKILL.md:14)、结构 DB [末段](/Users/alexhuang/workspaces/github/data-engineer-agent/docs/hiagent/versions/v5/skills/table-schema-query-db/SKILL.md:72)、字典 DB [末段](/Users/alexhuang/workspaces/github/data-engineer-agent/docs/hiagent/versions/v5/skills/dictionary-query-db/SKILL.md:70) 重复承担部分主流程判断。当前具体次数一致，不将此认定为已发生数字冲突。

完善规则：主提示词作为预算、状态转移和完成标准的权威；SKILL 接收剩余额度并保留必要的领域门槛。每个 SKILL 顺序保持“调用条件 → 操作步骤 → 完成标准 → 输出字段 → 字段/SQL参考”。优先用正向动作表明确下一步，必要禁止条款保留为短门槛，减少同义重复。

## 架构诊断与证据边界

| 层级 | 本次可判断什么 | 尚不能判断什么 |
| --- | --- | --- |
| 主提示词与技能文本 | 阶段边界、唯一性范围、回传字段、重复规则及输出要求 | 实际模型遵循率 |
| 工具选择/解释 | 可以推演哪些含糊规则会影响路由和结果解释 | V5 实际调用是否越级或被跳过 |
| 工具执行 | 当前文档要求实际 DB 返回；SQLite 样例可执行 | 平台是否有必经核验、参数绑定和程序级次数门禁 |
| 会话、记忆与持久化 | 文档允许复用当前问题证据，但状态/恢复记录不足 | 平台如何裁剪历史、持久化、更新或污染记忆 |
| 隐藏重试、NL2SQL、输出处理 | V3 用户反馈实际 SQL 含 LIMIT，存在回查意图 | LIMIT 注入层、是否隐藏二次模型调用、UI 是否改写回答 |

据当前证据，优先问题是阶段语义和信息交接，不能直接归因于模型能力、平台隐藏修复或记忆污染。当前可以确认五份文件只提供文字约束；平台是否另有硬约束未知。

如果目标是程序级“不能越过 DB / 不能超过执行次数”，应先查清 HiAgent 已有的工作流条件、执行上限或超时能力及实际轨迹；有可用能力才按真实平台配置落实。此次未访问或配置平台，不修改本仓库 Java 项目，不编造平台参数。

## 优化实施顺序

1. 核对平台执行边界及真实调用轨迹，区分文本约束与硬限制；这项与文件修正规则可并行，不因缺内网资料停止文本审查。
2. 先修 H01：统一结果状态及允许动作，区分定位失败、成员未匹配和数据不完整。
3. 再修 H02：建立轻量回传约定、任务记录、统一计数与继续的完成条件；不需要增加新业务 SKILL。
4. 修 H03 和 M01：明确用户范围/候选范围/DB范围，核对查询谓词和局部唯一性。
5. 修 M02 和 L01：按通用缺口定义澄清、成功/待选/部分/失败答复；收拢规则和步骤，不新增业务问题列表。
6. 完成 M03 行为验收，用轨迹和真实结果判断。只有内网证据才能证明改动改善了循环、准确性、耗时或友好性。
