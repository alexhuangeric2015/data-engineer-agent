## 文档复核补齐的边界

1. 取消默认完全重复合并，同时保留只对身份候选使用 DISTINCT；COUNT DISTINCT只为统计，不删除码值明细。
2. 数量是独立口径：全类型统计不能证实单值完整，单值P也不能当字典N；COUNT或CASE的条件须与相应真实范围一致。
3. 有中文/版本限定须进入类型完整范围；同英文不同版本不能把统计混加给某个版本。
4. 字典统计安排在取数阶段而非最终自检；错误/额度不足明确统计未取得，保持部分状态，无恢复循环。
5. 原描述外文也保留，中文说明/用户要求的翻译另列；不因友好表达而重写数据。
6. 业务请求完成和约束通过分开；输出容量不足、平台限制和统计失败不伪称完整。纯Markdown没有新增前端分页功能。

## 下一步内网验收

优先用35项回归里的T32–T35及固定五任务，核对每张码值表下方的SQL N/M、本次P和R/D。特别检查完全重复行、同码异义、单值查询、空值和统计失败；对实际原始记录按多重性和顺序核对，不仅比去重集合。若模型仍分类或省略，即使数量对也不能通过。

建议优化按证据推进：先看少做整理是否减少模型阶段耗时；多类型统计合批、同轮有效结果复用；单码值继续精准过滤，避免默认读全表。若仍慢，分别记录KB、SQL和模型生成耗时再找瓶颈。平台如已有确定性表格组件再考虑DB数据直达组件，本次不假设可用、不改前端。
