## 架构判断

六项业务能力共享智能体运行底座，不要求分别部署六个 Agent。优先复用 HiAgent 的模型调用、知识检索、工具调用与已有工作流能力；图中的具体状态存储、异步回调、任务门禁等逻辑能力，需要先核验平台支持情况。只有确认平台不能覆盖时，再决定由外部服务补齐。

主要依赖分为三条：

1. 模型服务：大语言模型负责理解、规划和生成；采用向量检索时需要 Embedding，重排模型按效果需要选择。模型可以由企业服务或外部 API 提供，不预设必须新建 GPU 集群。
2. 知识与事实服务：知识库提供候选定位和规范解释；数据库或权威平台提供精确资产事实。业务语义包括术语、指标口径、字段字典映射和企业分层规范，需要来源、版本和确认状态。
3. 工具与执行适配：接入元数据、代码、SQL 检查、调度、质量和监控能力。MCP 是接入方式之一，也可直接复用平台工具或 HTTP API。实际执行仍由对应数据库、计算引擎、调度或质量平台承担。

SKILL 是任务步骤、输入输出、完成条件和边界的载体。提示词和 SKILL 的文字约束不能代替确定性的权限检查、状态流转、执行校验和调用次数控制。图中 MCP 采用 Host/Client/Server 的职责边界，参考 [MCP 官方架构说明](https://modelcontextprotocol.io/specification/draft/architecture/index)。SKILL 与工具连接的职责区分参考 [Anthropic：Agent Skills](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)。这些资料不证明当前 HiAgent 部署已支持相应接口或文件加载方式。

## 当前起点与待确认条件

用户明确拥有数据库表结构和知识库。按当前 HiAgent 运行说明，表字段及码值查询采用知识库定位、数据库核验；已有查询路径不代表所有场景或新架构组件已经验收。当前运行说明中的 `related_column_en` / `related_column_cn` 字典名称语义继续有效，不因本图重定义。

尚需确认的条件包括：

- 模型服务的具体接入、配额与模型版本。
- 知识库内容是否包含有效的指标口径、分层规范、存量 SQL 和故障手册。
- 是否可以受控只读查询真实业务数据、查看执行计划，并使用隔离测试环境。
- 资产、血缘、代码、调度、质量、监控平台是否存在，其 API、权限和接入条件是什么。
- HiAgent 的工作流、任务持久化、异步结果和 SKILL 附属文件读取能力。

图中企业平台表示需要依赖的能力，可复用现有系统；不要求将这些能力全部新建成独立产品。独立向量库、全文索引和图存储是可选实现，按平台检索效果、精确查询和血缘遍历需求决定，不能仅因目标宏大而全部引入。现有知识库可以封装内部检索能力，当前没有独立向量库不妨碍先验证现有检索路径。

## 交付与验收边界

推荐按“资产与规范可核验 → 设计与代码可评审 → 测试环境可验证 → 执行平台可闭环”推进。该顺序是讨论建议，尚未替代客户截图中的 P0/P1/P2 业务优先级；每项 P0 都应进一步区分建议、生成、验证、执行四种交付深度。

- 生成 SQL：核验字段、字典和口径；语法正确不等于业务结果正确。
- SQL 优化：性能结论需要对应引擎上的执行计划及前后对比。
- 分层建模：ODM/CDM/FDM/PDM 的企业定义、粒度与历史处理规则必须确认。
- 质量检查：准确性需要权威规则或对照；波动性需要历史基线和适用阈值。
- 自主修复：明确适用故障、授权范围、幂等条件、重试上限、回滚方式和修复后复验。
- 资产盘点：需要采集范围、成功状态和版本快照；检索未命中不能作为资产失效证据。

图中连线表示调用或依赖方向；工具结果、检索证据和运行状态按原路径返回，未重复绘制反向连线。生产执行闭环为：生成方案 → 校验 → 按授权执行 → 收集结果 → 验证效果或恢复。知识与元数据持续更新通过原权威来源及其采集机制完成，不由模型记忆承担。
