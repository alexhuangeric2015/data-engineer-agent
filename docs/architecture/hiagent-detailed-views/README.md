## 关键契约：把图落到实际实现

### 03—04：资料进入运行知识的门槛

| 事件 | 最少输入或证据 | 实现责任 |
|---|---|---|
| 原材料接收 | 原件引用、版本、提供方、适用场景及访问范围 | 项目组登记，已有采集优先复用 |
| 技术核验 | 对象真实存在性、字段/字典/关联范围、实际查询或原平台证据 | 系统研发、B1或现有DB工具 |
| 业务确认 | 定义版本、责任人、确认时间和可复核记录 | 业务负责人；模型只能提出草稿 |
| 发布准备 | 批次内对象ID与版本、结构记录、待索引条目及权限一致性 | B1治理组件/原治理流程，平台管理员 |
| 批次激活 | 结构查询及知识命中验证、旧版处理、回归结果 | 项目组/治理测试执行发布验收 |
| 发布失败 | 失败环节、受影响对象、旧有效版可用性和恢复条件 | 不激活半套资料，保留旧版或暂停相应范围 |

已确认与已生效不是同一状态；已生效也不代表任意用户可访问。资料版本改变时重新走确认和发布，历史证据不原地覆盖。图04中的冲突解决后重新提交待确认；发布失败修复后重新准备和验收，不能直接修改状态为生效。

平台不支持按状态/版本过滤时，可先使用独立的已发布资料集和人工发布清单。不能把“忽略草稿”只写进提示词就视为完成隔离。HiAgent能否自动上传更新、切换绑定和恢复跨轮状态仍需内网证据，缺能力时用明确的人工步骤承接。

### 05：对象和版本的边界

图05是逻辑关系图，不要求按图新建产品或数据库。PK表示逻辑唯一键，FK表示明确的对象版本引用；同名跨系统资产通过来源范围和原标识区分。模板收集ID需要映射原系统标识，不替换现有数据库契约。

指标定义与技术实现分开，来源映射同时引用指标版本和资产版本；术语关联并不等于确认后的计算规则。任务基准引用采用的定义/资产版本，成果版本绑定任务修订号及内容摘要，验证运行绑定成果版本、实际引擎、数据快照和规则版本。正式确认、发布和执行权限必须有可信记录，不能靠模型生成的ID或状态成立。

本图聚焦关键关联，没有穷尽所有字段、实体和约束。正式物理设计阶段再补完整确认记录、发布明细、来源证据、索引与唯一约束。现有`table_schema`及`data_asset_code_kb`字段含义保持不变。

### 07：查询分支及退出规则

| 分支 | 进入条件 | 必须发生的动作 | 禁止的结果 |
|---|---|---|---|
| A 精确取数 | 已有足够身份和范围证据；依赖父对象已确认 | DB取原始明细及适用统计，返回来源和真实覆盖范围 | 不能把KB片段视为精准事实，不能将部分返回称全量 |
| B 等待选择 | 同名、近似、版本、字段或映射歧义 | 先DB核验候选，保留原目标/候选映射/阶段；下轮恢复 | 不能自动选Top1；未确认不取依赖它的下游结果 |
| C 无定位标识 | KB没有召回可用标识 | 跳过后续身份DB请求，结束该定位分支并提示收敛信息 | 不作全库语义猜测或无限检索，不宣称数据库不存在 |
| D 工具失败或截断 | 权限、超时、技术失败、行数限制或真实分页未完成 | 失败与零行区分；保留成功项、已取得范围和未完成原因 | 不将失败写成无数据，不虚构分页、数量或成功状态 |

图07的②返回候选后，只有有标识的分支进入③；图中C为提前退出路径，不意味着先查DB再判断KB是否为空。已确认父对象内成员可以复用有效定位，不为每个字段重复完整检索。表字段路径与独立字典路径分别遵循现有完整查询SKILL，图中的B1是工具边界，可由现有DB能力承载。

跨轮恢复须检查会话隔离、候选集合和证据有效性；无可靠状态时请求明确标识。明细、修正、计数和分页受所用运行版本预算和工具真实能力约束，不因改画时序而自动增加调用额度。读取SKILL参考文件不等于核验数据库。

### 08—09：校验、确认和执行的边界

| 环节 | 进入条件 | 输出证据与失败处理 |
|---|---|---|
| 生成草稿 | 基准有效，依赖口径/映射充分 | 设计、SQL、所用证据、任务修订和内容摘要；缺口时停止依赖部分 |
| 静态检查 | 成果具体版本、目标引擎和规则版本明确 | 语法/引用/规则的实际结果；失败不进入试跑 |
| 测试与对账 | 静态通过且测试环境、权限及资源范围可用 | runId、真实引擎状态、结果与独立预期对比；不可用标未验证 |
| 业务复核 | 可复核的成果与适用测试证据 | 责任人对本版结果的确认；不能以模型自评代替 |
| 发布或写操作【后续】 | 可信审批绑定具体内容、环境、身份与操作范围 | 原平台真实执行结果；旧授权对变更后的版本不生效 |

图09分别画出业务基准、成果验证和发布授权三个区域，区域之间通过明确证据约束关联，不自动同步状态。验证失败、未执行、部分结果都不会沿成功箭头推进“本版本已验证”。修改内容必须生成新版本并重新检查。既有人工试跑可以保留，但须注明执行人、环境、版本与原始记录，不能伪装成工具自动执行。

### 10：部署图仍需落地核验的事项

1. HiAgent到模型、知识库、事实工具的实际协议、网络及授权身份。
2. 数据库返回结构化行、实际SQL、统计及可靠分页的能力。
3. 后端到测试引擎的受控连接、允许操作、资源上限和超时。
4. B5或现有任务系统是否能可靠保存版本、证据和跨会话续接信息。
5. 质量、调度、代码和日志平台的存在性、接口、身份透传及原审批流程。

图中没有虚构IP、端口、机器数量或GPU配置。已有知识库不等于需要另建向量数据库，MCP也不等于必须额外部署一套网关。首期按已证明的缺口补适配，具体资源与负载依据前述方案实测。
