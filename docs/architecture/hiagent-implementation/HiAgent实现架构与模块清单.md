# 基于 HiAgent 的数据研发工厂：实现架构与模块清单

日期：2026-10-21。性质：独立实现讨论稿；原 `data-development-factory` 图纸及说明保持不变。所有 B 类模块和工具名称均为拟议设计，不表示已编码、已部署或 HiAgent 自带。

## 1. 项目到底交付什么

建议交付四类工程资产：

1. **HiAgent 应用配置包**：应用、模型与知识库绑定、场景 SKILL、主提示词、工作流和工具绑定清单。
2. **数据研发业务后端**：按五个业务模块组织确定性查询、检查、执行适配与成果记录；初期可用一个进程部署，不拆五套微服务。
3. **平台适配与知识资料**：对接已有元数据、代码、计算、质量、调度等平台；整理可版本化的规范和业务口径。
4. **评测与运维材料**：固定任务、标准答案或确定性判据、实际工具轨迹、配置版本、回归结果和排障记录。

当前优先复用 HiAgent 对话入口，不另起前端工作台。后端也不另建一套自由规划 Agent：模型理解和生成留在 HiAgent，后端提供输入输出明确的业务能力。

## 2. 依据和限制

已确认的起点：HiAgent 上有这套资产问答应用，使用知识库定位、数据库核验表字段和码值；不能把资产问答路径推广成全平台执行能力已经具备。V10 是一个完整查询 SKILL 包的设计交付，附属文件加载和真实部署仍需实测。旧文档中的“四个场景技能”和旧 V8 查询技能拆分，不覆盖用户后续采用一个完整查询 SKILL 包的选择。

本设计不读取仓库 Java 实现推断 HiAgent，也不将旧方案中资产平台、粒度说明、MCP 映射等“设计前提”当成当前事实。当前只明确有表结构、字典元数据与知识库，其他平台存在性及接入能力需核实。

[官方 HiAgent 对接说明](https://docs.volcengine.com/docs/DataAgentPrivate/ConnectwithHiAgent?lang=zh)可以支持知识引擎对接的总体背景，但不足以证明内网版本具备具体节点、暂停恢复、参数化 SQL、跨轮状态和回调能力。图中 H1—H4 是职责名称，不是照抄某版控制台菜单。

## 3. HiAgent 内我们需要配置哪些模块

| 模块 | 子模块与具体工作 | 外部关系 | 可检查交付物 |
|---|---|---|---|
| H1 数据研发助手应用 | 场景选择；请求理解；会话澄清；模型绑定；统一输出 | 加载 H2，检索 H3，进入 H4，调用 B 类工具 | 应用配置、主提示词、模型与工具权限清单 |
| H2 场景 SKILL | 资产查询；需求解析；分层建模与设计评审；代码生成与评审；质量规则；调度与运维 | 按场景使用 B1—B5；SKILL 不直接等于远程接口 | 各场景输入、前置条件、步骤、工具合同、完成条件、失败和输出规范 |
| H3 知识与模型配置 | 业务术语；指标口径；分层规范；编码/评审规则；历史方案；故障手册；知识库及模型版本 | 资产问答新对象仍先知识库定位，再 B1 或现有 DB 核验 | 资料清单、责任人、来源与版本、绑定和检索验收记录 |
| H4 场景工作流 | 结构化提取；事实查询；缺口判断；成果生成；校验工具调用；结果回传 | B5 供跨任务版本/状态；B2—B4 返回真实检查和执行状态 | 流程配置、节点输入输出及调用轨迹 |

H2 是能力目录，不要求一次注册六个入口，也不要求总 SKILL 递归调用子 SKILL。现有 `data-asset-query` 可保留为一个完整查询包；新增场景按平台实际加载能力选择独立包或复用公共参考，并以可维护的单一来源发布。技能数量和实际工具调用次数分开管理。

H4 优先使用平台原有变量、条件、工具和代码节点；实际不具备的能力要缩小场景或由明确的后端业务操作补齐，不把“模型记住状态”当成确定性实现。工具内部重试无法观察时不能声称已经限制。

## 4. 项目后端需要开发哪些业务模块

### B1 资产与业务语义模块

| 子模块 | 实现职责 | 复用来源与边界 |
|---|---|---|
| 结构化事实查询 | 核验候选；取表字段、字典原始明细和统计；返回真实范围、来源和完整性 | 首期复用现有元数据表和数据库能力；工具不足才补参数化查询适配 |
| 术语与指标解析 | 按已知名称或标识读取定义、粒度、单位、维度、过滤及版本 | 知识资料先整理；正式指标事实优先取已有指标平台，未提供写缺失 |
| 字段字典映射 | 读取已确认映射，区分缺失和冲突；精确码值查询 | 继续使用已确认的 related 两列语义，不重新猜字段绑定 |
| 资产采集与盘点 | 在授权范围采集；记录批次成功情况；快照差异；失效候选 | 后续复用原平台采集；不以 KB 未命中删除资产 |
| 血缘与影响查询 | 读取原平台真实血缘；存量 SQL 分析结果标来源与解析范围 | 首期没有血缘就明确缺失；不能以字段同名当血缘 |
| 元数据补全建议 | 输出缺失描述、候选解释和依据，等待治理责任人确认 | 建议与正式事实分开，正式写回后置；不直接建设全套治理平台 |

**与 HiAgent 的关系**：H3 提供语义定位，H2/H4 将候选标识交给 B1 核验；返回的事实用于设计和代码生成。B1 不另做一套生成式业务问答。

### B2 研发校验与交付适配模块

| 子模块 | 实现职责 | 输入 → 输出 |
|---|---|---|
| 需求与模型合同检查 | 检查必需项、粒度、主键、分层和来源是否充分；不能代替业务判断 | 需求/模型草稿、适用规则 → 缺项与规则问题 |
| SQL 方言与静态分析 | 优先复用目标引擎解析器、编译能力或成熟解析组件，提取引用、检查语法和允许操作 | SQL、引擎与资产证据 → 问题位置与检查结果 |
| 规范评审 | 对可程序化的命名、分层、字段引用规则作确定性检查；开放性意见仍由模型给出并标依据 | 规则版本、设计与代码 → 问题、规则ID、证据 |
| 执行计划与试跑 | 受控 EXPLAIN、测试查询、资源和超时限制；样本结果对账 | 已检查SQL、测试环境、预期 → 实际运行证据 |
| 代码与发布适配 | 读取存量代码、比较差异、生成交付包或提交到既有流程 | 确定版本、已有流程许可 → 交付引用或发布结果 |

**与 HiAgent 的关系**：HiAgent 生成设计、SQL 和评审解释；B2 检查并返回事实结果，HiAgent 根据结果修改草稿。模型不能自己把“看上去没问题”写成编译或运行已通过。

先锁定一个 SQL 引擎，再选官方检查能力或解析组件；当前不指定通用解析器型号，也不自研 SQL Parser。没有测试接口时保留人工试跑和导入证据路径。

### B3 数据质量执行模块

| 子模块 | 实现职责 | 与 HiAgent 的关系 |
|---|---|---|
| 质量规则管理适配 | 规则对象、作用表字段、检查周期、阈值、例外与版本 | 模型推荐规则；经确认后保存为可执行配置 |
| 六类规则执行 | 完整性、唯一性、一致性、时效性、准确性、波动性 | 后端调用质量平台或受控引擎，返回检查运行ID与明细 |
| 基线与问题证据 | 历史分布、异常样本和对照结果 | 为模型解释提供真实依据，不能自行编造阈值 |
| 影响定位 | 结合真实血缘、任务与数据分区定位影响范围 | 模型组织说明，工具返回实际关联范围 |
| 修复与复验 | 仅执行白名单修复或既有流程，明确原值、回滚与后续检查 | 模型提出建议；后端验证授权和条件，执行后再次检查 |

已有质量平台优先适配其规则和结果，避免在项目中重建规则引擎。没有现成平台时先用质量 SQL 在测试环境验证少量规则；不把这个过渡方案称为完整质量平台。

### B4 调度与运行处置模块

| 子模块 | 实现职责 | 与 HiAgent 的关系 |
|---|---|---|
| 作业与依赖读取 | 查询作业定义、真实上下游、周期和资源设置 | 支撑候选 DAG 和配置建议 |
| 调度配置检查 | 检查引用、循环依赖、时间条件、重复作业和必要参数 | HiAgent 提出配置草稿，后端检查 |
| 发布与运行适配 | 调用原平台创建/更新/测试，返回作业及实例标识 | 后端校验授权，原平台真正调度 |
| 日志与实例查询 | 查询失败、超时、运行日志和监控证据 | 模型据此诊断，缺证据时保留假设 |
| 受控处置与恢复 | 白名单重试、补数、重跑、状态查询和恢复验证 | 后端按原平台能力检查幂等、次数和影响；无权时仅建议 |

任务的长期运行在原调度/计算平台，不能让一个 HiAgent 会话一直等待。最小实现为返回实例ID并按需查询；有可靠事件接口和鉴权后，再接告警或回调。任务重试不等于修复数据错误。

### B5 任务与成果记录模块

| 子模块 | 实现职责 | 不承担的职责 |
|---|---|---|
| 需求基准与版本 | 保存目标、粒度、口径、范围、引擎及确认版本 | 不代替业务方确认口径 |
| 成果与证据记录 | 关联设计、SQL、质量规则、调度草稿、报告及来源证据 | 不复制所有业务数据与日志 |
| 验证状态投影 | 区分草稿、待确认、已确认、未验证、验证失败、可交付及失效 | 不以模型文字当检查通过证据 |
| 确认与授权记录 | 将用户身份、任务版本、成果内容摘要和授权范围绑定；变更后失效 | 不允许模型传入 confirmed=true 就升级为已确认 |
| 查询与续接 | 按任务和版本返回成果与下一步缺口 | 不再实现一套 Agent Planner 或调度引擎 |

首期只做资产查询或草稿交付时，可以用现有交付记录、版本文件和人工确认记录承载最小成果包。需要多轮长任务、跨会话续接或发布时，必须有可可靠访问的版本化记录：优先适配既有任务系统，缺失才补项目持久化。

**确认入口的可信性**：执行授权要来自既有审批/发布流程，或能验证用户身份和具体版本的确认接口。若 HiAgent 只提供自然语言会话、无法提供可核验的确认事件，则只记录“用户在对话中表达认可”，生产发布继续走原流程，不把它转换成机器可执行的授权。人工测试证据也要标明执行人和适用版本，不能伪装为自动工具证据。

## 5. 共同接入模块，不额外拆成一组服务

| 公共子模块 | 作用 |
|---|---|
| MCP/插件/HTTP 适配 | 将业务方法暴露给 HiAgent；优先复用已有连接，按实际版本选择协议 |
| 身份与数据权限 | 接收经验证的调用方身份，按授权限制库表、行列和读写操作；不能信任模型自报用户名 |
| 连接与凭据 | 对接原平台连接配置；凭据留在执行边界，不回传给模型 |
| 参数和执行保护 | 结构化参数、允许操作、超时、资源限制、幂等键、有界重试 |
| 日志与审计 | taskId、revision、工具操作、脱敏关键参数、范围、行数、耗时、结果与停止原因 |
| 平台适配器 | 分别对接元数据、代码、引擎、质量、调度和日志；复用 SDK/API，不让主业务模块拼平台协议 |

MCP Server 不逐项等于业务模块。初期可以一个 MCP 入口提供多个清晰工具，也可复用内置数据库和知识库工具。协议层只做映射，业务门禁在后端业务边界执行；内部方法之间直接调用，避免本机模块互相经 MCP 绕行。

## 6. 给开发人员看的最小工具合同

以下为**拟议业务操作名**，不是平台现有工具，也不是已经存在的 API。实施时再按实际服务映射名称和字段。

| 操作 | 模块 | 核心输入 | 核心输出 |
|---|---|---|---|
| 核验资产与取详情 | B1 | 候选标识、查询范围、事实投影、分页位置 | 原始记录、实际范围、来源版本、覆盖与冲突 |
| 读取指标口径 | B1 | 指标标识或已定位候选、适用版本 | 定义、粒度、过滤、单位、维度、缺项 |
| 检查设计与SQL | B2 | 任务版本、成果内容/引用、目标引擎、规则版本 | 检查项、问题位置、证据、是否实际执行 |
| 测试运行 | B2 | 经校验成果版本、环境、参数与资源上限 | runId、真实状态、样本或对账摘要、证据引用 |
| 执行质量检查 | B3 | 规则版本、表分区与时间范围、环境 | qualityRunId、规则结果、问题明细引用 |
| 检查/发布调度配置 | B4 | 配置版本、环境、经验证授权引用 | 问题或原平台jobId、instanceId及状态 |
| 查询运行/提出处置 | B4 | jobId/instanceId、范围，处置时附版本和授权引用 | 日志证据、处置受理结果、验证状态 |
| 保存/读取任务成果 | B5 | taskId、期望revision、内容及来源 | 新revision、成果ID、验证状态、待办缺口 |

通用返回值区分成功、部分、歧义、未找到、失败、未执行与不支持。失败不能转成“资产不存在”；未执行不能转成“验证通过”。分页和数量口径由事实服务报告，不由模型猜测。

## 7. 客户六项能力如何落实到工程模块

| 客户目标 | HiAgent 内主要工作 | 后端主要依赖 | 真实完成条件 |
|---|---|---|---|
| 需求解析与拆解 | 需求SKILL提取口径、缺口和任务草稿 | B1查询来源，B5记录确认基准 | 关键口径与范围由责任人确认，关联证据可复核 |
| 代码生成与重构 | 编码/评审SKILL生成和修订代码 | B1事实、B2校验、B5版本 | 对应引擎检查及业务测试；性能结论另需对比 |
| 分层建模 | 建模SKILL按企业规范生成方案 | B1存量资产，B2规则，B5设计版本 | 粒度、关联、生命周期有依据且经过评审 |
| 质量校验与修复 | 质量SKILL推荐规则、解释异常 | B3执行与复验，B1血缘，B5版本 | 真实检查、问题证据、授权修复及后验结果 |
| 调度与运维 | 调度/运维SKILL生成配置和诊断建议 | B4检查执行、B3复验、B5证据 | 真实实例与日志可读；处置有边界并验证效果 |
| 资产检索与盘点 | 查询SKILL定位、澄清、解释 | B1核验/采集/差异，B5按需记录 | 原来源范围有覆盖证据，补全和失效有确认依据 |

## 8. 从目前只有表结构和知识库怎么开始

| 建设包 | 具体新增工作 | 可验收产出 | 暂不扩张的内容 |
|---|---|---|---|
| 第一包：资产事实可用 | 配置H1/H3，验证现有完整查询SKILL；B1优先复用现有KB和DB，只有查询合同不足才开发适配 | 按真实资产问题核验候选、字段、映射、码值及完整性，缺口和失败能正确区分 | 不先建独立向量库、全量治理和任务中心 |
| 第二包：研发辅助可用 | 补需求、建模、编码评审SKILL；整理企业规范；B2接一个引擎的检查；用最小成果包记录版本和证据 | 一个真实需求产出确认单、来源证据、设计、SQL和评审结果；试跑可先人工 | 不将草稿宣称成生产任务；不同时适配所有引擎 |
| 第三包：质量和调度可验证 | B3/B4接测试环境、真实质量和调度接口；B5补可靠记录或适配现有记录 | 配置可检查、任务能运行、质量有结果、失败可定位 | 没接口时停在配置草稿，不假装自动执行 |
| 第四包：受控自动化 | 按高频场景完善正式确认、授权、幂等、补数与复验、告警接入、盘点快照 | 少量白名单场景可以从问题发现到恢复形成证据闭环 | 不对全部故障承诺自主修复 |

建设包按最早可验证闭环组织，不替代客户P0/P1业务优先级。第一包通过后即可选第二包的一个真实场景，不必先完成整个B1资产治理目录。所有包都有上述明确产出后再扩大范围，不把平台能力核验当成无限期前置调研。
