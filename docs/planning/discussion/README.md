## 如何讨论和记录

先讨论方案主线与核心业务场景，再讨论模块和系统分工，最后确定页面、图页与视觉。可直接引用P、G、S、M、D编号提出意见：例如“P11需要补实际消费机制”“G09需明确哪些信息返回”“D03先只做管理和映射”。

- **P**：当前PPT内容索引；**G**：当前图集索引。
- **S**：场景；**M**：建设模块；**D**：待讨论决策；**C/R**：案例及理念来源。
- 已确认的用户边界不重新当成未决事项；建议和待盘点事项不写成已确认事实。
- 每轮把结论写回相关章节和决策表，保留未决问题。未经确认，不把建议自动转成既定建设范围。
- 当前30页与14张图只是资料映射，不锁定下一版数量。下一版仍需同时有高度、有细节，不靠增加页数代替内容深度。

## 生成下一版前的内容完成条件

1. 方案定位和优先场景清楚，当前建设与目标规划区分明确。
2. 每个核心模块具备“缺失后果、建设内容、工作机制、系统分工、依赖难点、成果与收益”。
3. 每张图要回答的问题、关键对象、关系方向和权威来源已明确。
4. 案例与示例标识清楚，事实、建议、目标不混用；没有无依据的效果承诺。
5. PPT叙事和独立架构详图目录已确认；重要未决事项已解决或明确为保留条件。
