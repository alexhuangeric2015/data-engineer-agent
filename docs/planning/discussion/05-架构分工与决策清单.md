## 一、已确认的规划边界

| 编号 | 已确认内容 | 后续表达要求 |
| --- | --- | --- |
| F01 | 基于HiAgent，当前仅建设数据资产智能体及其配套资料治理。 | 长期三类九种角色与当前范围分别表达，不以目标图认定已部署。 |
| F02 | 生产类5种：需求分析、设计、开发、测试、评审；运营类3种：资产、运维、治理；分析挖掘类：分析。 | 专业角色不等于固定部署实例数量，当前资产角色清楚标识。 |
| F03 | 专业Agent内部规划，可引用其他Agent。 | 不新增必选总控Agent层，不强制所有任务采用同一协作链。 |
| F04 | SKILL定义方法与规则，资源引用及实际调用由Agent负责。 | 不画SKILL调用其他SKILL、知识库或数据库的关系。 |
| F05 | 当前知识库定位候选，外部结构化查询数据库核验资产事实。 | 不用知识片段或模型记忆代替实际记录，字段字典映射不当物理外键。 |
| F06 | 实际血缘经数据资产平台查询。 | 区分业务关系、语义映射与真实加工血缘；说明来源、时点和覆盖缺口。 |
| F07 | 全景第06层为系统与平台，覆盖开发、资产、调度、血缘、质量、数仓与计算等。 | 原平台继续管理权威内容和执行过程；项目复用与补强边界明确。 |
| F08 | 指标能力优先盘点与复用，定义管理和计算服务分别规划。 | 不自动新建另一套权威平台，不将指标目录等同计算引擎。 |
| F09 | 部署保持逻辑规划深度。 | 不预设实际网段、机器、模型位置或云上/私有化方式。 |
| F10 | V0.3能力全景是结构基准；PPT和独立详图分别设计。 | 不因汇报页空间限制删掉独立全景的职责、支撑列、保障列和调用链。 |
| F11 | 要高度也要细节，不包含预算测算，不设技术备答章节。 | 机制、难点和分工融入主线；本轮大纲讨论确认后再制作新版本。 |

## 二、建议保持的平台职责

下表是规划职责原则，具体产品可一体化承载多个职责，实际能力需盘点。

| 对象 | 权威或主要职责 | 智能体/本项目的作用 | 应重点确认的接口与结果 |
| --- | --- | --- | --- |
| HiAgent | Agent、会话、资源引用、知识与数据工具接入。 | 专业配置、任务方法、上下文组织、协作和成果核验。 | 可用引用方式、返回结构、状态、追踪与权限支持。 |
| 数据资产/指标平台 | 目录、业务定义、模型与指标、归属，以及血缘服务入口。 | 检索、消歧、语义补强建议、查询与来源解释。 | 定义与版本、指标实现、元数据、真实血缘覆盖及更新。 |
| 数据开发平台 | 代码、模型、调试和原发布流程。 | 生成草稿、检查、组织调试与交付材料。 | 草稿/调试/提交/发布的权限和状态区别。 |
| 数据调度平台 | 依赖编排、任务实例、日志、运行与恢复。 | 查询事实、组织线索、提出受控处置建议。 | 实例标识、时间范围、日志、状态和处置结果。 |
| 血缘工具 | 解析、采集实际加工依赖。 | 经资产平台消费其结果并辅助解释。 | 表/字段覆盖、采集时点、动态SQL和跨系统缺口。 |
| 质量工具 | 规则执行、质量检查与结果。 | 建议规则、调用检查、关联结果与治理问题。 | 规则归属、检查范围、结果时点、证据与整改状态。 |
| 数仓/计算引擎 | 存储真实数据、按授权查询计算。 | 组织查询或复用指标服务并核验结果。 | 用户/服务身份、行列权限、资源限制、结果与异常。 |
| 业务与数据责任人 | 业务口径、关键取舍、审核和成果确认。 | Agent辅助提取、比较、成文和提供证据。 | 明确谁确认、何时确认、确认结果如何留存和更新。 |
