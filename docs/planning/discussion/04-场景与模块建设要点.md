# 场景与模块建设要点

状态：讨论工作稿。S编号用于选择代表场景，M编号用于展开建设内容；它们是内容归类，不代表新增Agent、平台、采购项或本期实施承诺。

## 一、场景内容清单

### S01 当前：数据资产发现与解释

- 角色与问题：研发、治理或分析人员按业务描述找表、字段、字典与码值，当前容易依赖翻资料和人工确认。
- 处理链路：识别对象与范围 → 知识索引定位候选 → 歧义确认 → 外部查询库核验 → 表/字段/字典/码值关联解释 → 追问与资料反馈。
- 必备依据：治理后的表字段、字典类型、原始码值与业务说明；有效父对象与候选标识。
- 交付成果：实际对象和记录、来源与范围、缺失说明、相关追问；保留前导零等原值，不编造释义。
- 建设与难点：M01、M02、M05、M07、M08；同名对象、资料质量、索引与事实更新一致性。
- 收益观察：定位正确性、完成同类查询所需时间、人工确认次数、资料缺口闭环。下一步选择一条真实高频问题贯穿演示。

### S02 规划：指标口径查询与复用

- 角色与问题：需求方、开发与分析人员重复解释同名指标，不同报表或Agent可能采用不同范围、维度和时点。
- 处理链路：查指标定义与有效版本 → 澄清对象、维度、期间与条件 → 选择受控实现 → 查询或计算 → 结果与口径一并返回。
- 必备依据：指标契约、责任版本、物理映射与已有API/已验证SQL；不能将知识片段或模型猜测当权威指标定义。
- 交付成果：复用建议、统一口径说明、受控计算结果及来源，或缺少定义/实现的明确清单。
- 建设与难点：M02、M03、M06、M07；历史口径、实现一致性、版本同步及实际消费是否收敛。
- 收益观察：审核指标复用、重复定义/重复开发、口径争议和结果一致性。是否覆盖实际计算、覆盖到什么粒度，见D03。

### S03 规划：需求复用、澄清与成文

- 角色与问题：业务、数据产品与研发人员反复调研已有指标、报表和模型，口径和验收要求易遗漏。
- 处理链路：解析目标与对象 → 检索相似成果 → 比较覆盖与差异 → 澄清阻塞项 → 按模板形成需求与验收条目。
- 必备依据：存量成果目录、指标/术语、需求模板、相似案例及可追溯来源。
- 交付成果：复用/改造/新建的建议与依据、结构化需求、假设与待确认事项；相似度不自动等于满足需求。
- 建设与难点：M01—M04、M06；隐性业务规则、元数据覆盖和人员确认；追问需聚焦阻塞项。
- 收益观察：重复调研、需求遗漏、确认往返和成果采纳。不将估算工时或预算纳入本次主线。

### S04 规划：设计、开发、测试与评审协作

- 角色与问题：设计口径、模型粒度、字段标准和代码验证跨多人交接，容易返工或遗漏。
- 处理链路：确认需求 → 复用模型与码值 → 形成设计 → 生成代码草稿 → 原平台调试/测试 → 规则与专家评审 → 原审批发布。
- 必备依据：已确认需求、同域模型、物理schema、规范模板、测试判据、原平台环境、实际血缘覆盖。
- 交付成果：设计与代码草稿、用例与实际结果、对账差异、评审问题、来源及关键假设。
- 建设与难点：M01—M07；模型粒度/关联基数、方言、业务正确性、独立测试判据和跨平台状态。
- 收益观察：规范遗漏、返工、交接问题、测试覆盖与采纳。SQL能运行不等于业务正确，生成代码不等于获准发布。

### S05 规划：质量、变更影响与运行诊断

- 角色与问题：治理和运维人员跨资产、质量、调度及日志系统取证，异常影响和整改责任不易确定。
- 处理链路：定位异常对象与实例 → 查询口径/血缘/质量/日志 → 组织证据与假设 → 给出范围与建议 → 原平台处置 → 验证并回流规则与资料。
- 必备依据：经资产平台查询的真实血缘、质量检查结果、调度实例与运行日志，保留覆盖范围及采集时点。
- 交付成果：证据清单、原因线索、受影响范围与缺口、整改建议、责任与复核结果。
- 建设与难点：M01、M02、M04、M06—M08；动态依赖和跨系统血缘缺口、实例定位、根因假设、重试与处置状态。
- 收益观察：取证耗时、范围识别、问题闭环与同类问题复发。线索不是已经证实的根因，完整性不超出真实覆盖。

### S06 规划：指标分析与业务解释

- 角色与问题：分析与业务人员反复取数、核口径，报告结论缺少可复核的结果依据。
- 处理链路：明确问题与可比范围 → 查指标/维度与资产 → 授权查询与计算 → 对比/下钻/贡献拆解 → 结果核验 → 图表与解释。
- 必备依据：指标契约、模型与维度约束、数据时效及质量、计算工具和分析方法样例。
- 交付成果：真实计算结果、图表、来源版本、事实/假设/建议与适用限制。
- 建设与难点：M01—M04、M06—M08；聚合重复、缺失样本、时间可比性、结论边界和业务采纳。
- 收益观察：口径一致、取数与复核过程、报告采纳。贡献拆解与相关性不直接证明因果，不承诺开放式任意问数均准确。

## 二、核心模块建设要点

### M01 专业Agent与任务组织

- 缺失后果：通用对话难以承接有输入输出、规则和责任的专业工作。
- 建设内容：角色职责、任务边界、提示词/SKILL方法、资源引用、输出规范、协作与异常处理。
- 工作机制：主导任务的Agent规划、调用、观察、核验与汇总；按需引用同级Agent，不设必选总控层。
- 分工依赖：HiAgent承载，专家定义任务与判据，原平台执行；调用能力按真实配置验证。
- 成果与价值：可复用的专业服务配置和任务成果，减少交接损耗；难点是边界、上下文、协作开销与验证。

### M02 企业语义与资产内容

- 缺失后果：业务名难找资产，找对字段仍可能错联、错聚合或误解状态码。
- 建设内容：术语同义词、业务对象、模型粒度、关联键/基数、有效期、字典映射、责任和来源版本。
- 工作机制：业务表达先对应定义和候选，再映射物理实现；当前字典关系按实际父对象核验。
- 分工依赖：优先资产/模型/标准平台维护权威内容；项目治理并组织消费索引，专家确认业务语义。
- 成果与价值：受控语义、有效映射和可追溯说明；难点是历史规则、隐性知识、关系验证和持续更新。

### M03 指标定义、实现与消费服务

- 缺失后果：同名异义、反复解释、重复开发和跨报表结果难比较。
- 建设内容：标识、定义、公式、粒度、维度、条件、范围、版本、责任；经验证的SQL/API及物理映射。
- 工作机制：检索定义 → 消歧 → 选择适用实现 → 受控执行 → 返回结果、口径与来源 → 反馈变更。
- 分工依赖：指标责任人确认契约，原资产/指标平台管理，计算引擎执行；先盘点功能和接口，不能假定全部缺失或全部具备。
- 成果与价值：受控指标目录和消费方式，复用经审核口径与实现；难点在版本一致、历史口径、执行约束和消费收敛。
- 分层选择：定义管理与实现映射可先补齐；计算优先已有服务或受控SQL；新语义引擎/MQL属于条件性扩展，见D03。

### M04 规范、模板与专业方法

- 缺失后果：生成格式不一、规范遗漏、评审靠个人经验，成果难交接。
- 建设内容：结构化规范、机器可检查项、需求/设计等模板、SKILL步骤、证据要求与人工判断清单。
- 工作机制：Agent读取方法组织工作，规则工具执行确定性校验，人员处理业务合理性、取舍与关键变更。
- 分工依赖：业务/数据专家维护标准，工具和原流程落实门禁；文档可辅助阅读，但提示词不代替硬控制。
- 成果与价值：规则清单、模板和方法包，减少遗漏与返工；难点在例外、冲突、主观项及验证样本。

### M05 存量治理与内容供给

- 缺失后果：索引召回不准、事实错误、口径过期，后续Agent共同放大资料问题。
- 建设内容：盘点、清洗校验、映射补全、语义候选、冲突处理、责任审核；知识与结构化数据加工、写入与验证。
- 工作机制：按业务关键性、影响、风险与使用需求排序；审核后形成索引和查询数据，源变更和失败反馈驱动更新。
- 分工依赖：数据责任方确认，原平台维护权威定义，项目组织加工；治理Agent是后续辅助角色，不是基础治理的前提。
- 成果与价值：问题清单、治理内容、知识文件和查询数据，提升候选定位及事实可用性；难点为存量质量、审核和双载体一致性。

### M06 平台连接与服务适配

- 缺失后果：跨系统仍靠人工搬运；API接通后也可能选错对象、越权或误读执行状态。
- 建设内容：目录、指标、血缘、开发、调度和质量等服务连接；身份、对象、范围、版本时点、状态、异常与证据契约。
- 工作机制：Agent组织请求，适配层按平台能力调用，原平台返回并执行，结果经过核验再用于成果。
- 分工依赖：原系统开放与改造，统一身份和实际引擎/网关权限；真实血缘服务入口为数据资产平台。
- 成果与价值：服务能力清单、适配与联调证据，缩短跨系统取证；难点在授权、环境、幂等/重试、异常和生命周期状态。
- 接入形式：API或MCP按条件采用，标准化接口不是业务语义、权限或数据质量的替代品。

### M07 结果核验、受控执行与人工确认

- 缺失后果：错误输出看似可信，操作边界不清；代码运行成功却无法证明业务正确。
- 建设内容：来源和范围核验、独立对账、质量/静态检查、关键确认、操作分级、失败状态与审计证据。
- 工作机制：数据与计算由工具返回；读取、草稿、调试、提交、发布分级；无权/缺失/超时按事实说明。
- 分工依赖：平台落实权限与硬门禁，专家提供业务判据；模型自评和置信度不能代替证据。
- 成果与价值：可复核成果和受控操作记录，减少漏错与风险；难点在独立判据、隐性规则、失败恢复和生产权限。

### M08 评测、反馈与持续运营

- 缺失后果：演示可用但真实任务退化，问题重复出现，内容过期无人维护。
- 建设内容：真实任务分类、专家答案、人工基线、调用与失败分析、内容更新、回归与责任安排。
- 工作机制：试用和日常失败回流到数据、规则、接口或模型问题，修订后复测同类任务。
- 分工依赖：业务、数据与平台共同维护；调用量不自动代表有效工作或业务收益。
- 成果与价值：基线任务集、复核报告、更新与改进闭环；难点是样本质量、可比性、采纳判据和责任持续性。

## 三、统一收益表达

收益分为预期机制与验证证据：先说明哪项工作将减少、复用或更可靠，再确定如何观察。指标目标应在试点基线上确认，不填无依据百分比，不开展预算或财务测算。

下一轮优先选一条当前S01与一条后续代表场景讲透，再检查其需要的M模块是否均有明确机制和责任。场景取舍见D02，模块范围见D04，收益定义见D09。
