# 字典类型候选定位

## 职责与边界

使用实际绑定的 HiAgent 数据字典知识库检索工具，将业务名称定位为字典类型候选。输入是用户原词及已确认的字段/业务范围，输出是候选代码与召回依据。不提供最终字典名称、码值或含义；所有事实和候选展示必须先经 `dictionary-query-db` 查询核验，最终回答由主提示词组织。

用户已给精确字典代码，或 DB 字段元数据已明确声明关联代码时，直接使用字典 DB，无需本 SKILL。用户只给码值或描述且没给类型时，优先用字典 DB 查候选类型，不靠向量召回判断这个值只属于一个类型。

## 数据线索

实际召回片段可能包含 `code_table_en_name`（字典代码）、`code_table_cn_name`（字典中文名）、`code_value` 和 `code_desc`。其中码值/描述仅帮助定位，不作为最终答案。本 SKILL 的来源是知识库；同名数据库表 `data_asset_code_kb` 的查询结果由字典 DB 提供，两者不能混用。

## 执行步骤

1. 保留用户原词、业务场景及已确认字段。“身份类型”与“角色类型”等相似术语不能自动互换，除非已核验元数据有明确别名或用户已确认。
2. 对实际绑定的数据字典知识库检索一次；可在一条检索中包含名称、字段和业务范围。不依赖索引文件，不要求读取指定知识文件。
3. 仅提取召回片段明确包含的字典代码和名称。代码缺失则标记“标识不完整”，不得根据中文名、字段名或 `_CD` 后缀生成字典代码。
4. 按字典代码去重，保留名称冲突信息，最多提交 5 个与原问题相关的候选。一个近似候选仍只是候选；不把 Top1 或相似度当作语义确认，不编造相关度百分比。
5. 交给 `dictionary-query-db` 批量核验候选类型。核验成功只证明类型存在；是否与用户原词等价、是否关联当前字段，由主流程按明确元数据或用户确认决定。
6. 未召回时报告“未召回”；主流程可按用户明确给出的中文名/代码在 DB 做一次精确核验。检索失败时报告失败，不根据常识补码值，不轮换关键词重试。

## 提交给主流程的结果

| 项目 | 内容 |
| --- | --- |
| 状态 | 候选待核验 / 标识不完整 / 未召回 / 检索失败 |
| 原始查询 | 用户原词及本次检索范围 |
| 定位来源 | 工具实际返回的知识库名称；未返回则写“名称未返回” |

| 候选字典代码 | 候选字典中文名 | 召回依据 |
| --- | --- | --- |
| <片段明确返回的 code_table_en_name> | <片段中的 code_table_cn_name> | <支持该候选的简短原文依据> |

候选表格只供主流程使用，不直接交付码值或含义。尤其不能根据检索片段给出“身份类型就是角色类型”的结论；需先 DB 核验名称，再由用户确认近似对象。

## 停止条件

本回合最多一次字典 KB 检索；返回候选、未召回或失败后交还主流程。不取“全部码值”，不以有限切片证明完整，不在结构 KB 与字典 KB 之间反复跳转。
